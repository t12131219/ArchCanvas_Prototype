# 阶段概览中的可选调用边界折叠

保留两个独立目标：F0 的合适语义折叠状态接近专用 Transformer 完全折叠图；F1 的较细语义状态接近其完全展开图。F1 下面继续保留更细源码事实。“完全折叠”以用户截图中的主要子模块、残差和跨区上下文为准，不能用把全图收成一个根节点来满足目标。本轮是通用增量，整体双目标尚未完成。

## 通用规则及其边界

在可缩放画布的“阶段概览”新增“摘要内容”选择器，默认仍为“运算与绑定”；显式选“调用边界”才折叠内部说明。适用对象是已有独立校验通过、包含源码读取的有界 DAG helper。判断依赖实际操作、来源读取、结果和切边，不使用 Transformer 名称、案例 ID、源码哈希或参考坐标。未知、条件、可变和逃逸关系继续作为真实边界保留，不能跨过这些关系补出透明计算。

调用边界卡片显示实际源码调用名、折叠操作数、结果算子、读取出现次数及已证明的共享调用身份。它不更换语义前沿，不减少阶段节点，不合并独立调用，也不主张源码读取值相同、纯函数或执行顺序。原始读取表达式、各算子输入槽、规范成员、依赖 DAG、来源归属和切边完整留在 IR、检查面板和 SVG 的 `<title>` / `data-call-boundary` 中。双击调用及其表达式分区可以继续展开。

这是一种较弱的边界表达，不能计作内部依赖已直接展示。`summary_coverage.status` 保持 `unfulfilled`，`form` 为 `call-boundary`；只有独立重建的卡片、实际打印内容和路由切边匹配时，`boundary_status` 才为 `fulfilled`。`detailed_relationships_fulfilled` 仍为 false。展开后须重新验证实际操作路径，不能用 accounting 或工具提示代替画面中的直接依赖表达。

Transformer F0 均为 28 图元／37 连接，仅两个源码读取 helper 的内部文字折叠。高度减少 16px、交叉少一处，但线长增加约 0.61%。另外两个普通案例也增加一处交叉。因此这是用户显式选择的细节取舍，不是保证几何单调改善的自动优化。默认 F0 及三张固定 F1 SVG 均逐字节不变。

目视审核中主要阶段仍保留，粗档两路输入及 mask 汇线仍拥挤、图面偏纵向，跨区上下文、整体方向和参考图仍有明显差距。F1 的整体组织也未因此改善。需要继续从通用来源分组、跨区域通道与局部语义前沿选择推进，不能仅靠降低说明密度宣称收敛。

另在临时实现副本探索过多消费输入的来源侧选择：Transformer 各候选交叉 10–14，均高于默认 9；普通小案例也多有退化，全部未采用。探索位于 `/tmp/archcanvas-input-facing-probe/`，不计入持久正式通过证据。

94 组／1031 项全量测试通过，包含 9 项新增定向测试：证明及打印内容篡改、切边丢失、共享调用、多个读取、条件／可变／未知／逃逸邻居、默认和非 stages 视图保留、改名、保存重开及规范源码投影。
