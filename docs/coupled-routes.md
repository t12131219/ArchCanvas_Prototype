# 在固定语义状态下联合重布两条相交连线

本轮继续向可审计、清晰的架构图推进，新增通用几何候选：单条连线重布不能改善时，释放实际相交的一对连线，同时保留其余已选路径，再比较两种布线顺序。规则不使用模型、类名、案例 ID、源码哈希、Q/K/V 名称或专用图坐标。

此前主图的第三组角色排列已经进入源码声明顺序候选，因交叉和线长增加而被拒绝。本轮先用真实最终渲染结果复测：单独重排仍从 12 增至 15 个交叉，因此没有强行统一角色顺序。随后固定节点和端口，检查两条线路互相占据可用通道的情况；这一方向同时在陌生汇合图和 Transformer 主图得到实际收益。

## 适用范围和接受条件

实现位于 `semantic_studio/publication-renderer.js` 的 `prepareCoupledRoutes`，在最终空白带压缩后运行，不参与语义前沿选择。只处理画布上的普通数据依赖；显式旁路、状态、迭代、上下文通道、反馈和控制线路保留已有策略。未知节点周围的普通连接仍可按真实几何组织，不据此解释其内部行为。

每轮最多比较 12 对实际相交的连线，每对两个顺序和两种拥塞代价，最多 48 次测量。每次只替换这一对的路径：节点、原始操作数、边属性、折叠状态、连线两端的具体坐标和侧面均保持不变。所有其余路径保持原样。候选必须满足：

- 交叉数严格减少，不能增加无关接触、不同值共线、路由失败或标签问题；不能引入新的无关接触对。
- 宽高和字号不退化；总线长不超过进入这一阶段时的 102%。该上限对整个阶段生效，不逐次累乘。
- 原有已应用约束、已实现的几何关系及所有直接表达目标保留。
- 拒绝的候选使用独立缓存和约束记录，不泄漏回已选图。

`paperCoupledRoutes:false` 可关闭这一阶段。手动偏移、打印视图、超过 128 条可见边时不执行。此前标题可通行规则继续有效；无需为了减少交叉重新把标题设成障碍。主图实际标题通行次数从 41 变为 39，是新路径选择的结果。

## 正式结果

基线冻结自提交 `568b56e`。20 个小案例用隔离的冻结渲染器和当前渲染器分别生成；三张大图的基线复用该提交记录的实际捕获，在读取前验证生产代码、输入、展示状态和 SVG/文档字节哈希。

## 验证

全量本地检查为 75 组、856 项通过，包含 7 项联合布线专项测试。历史角色前沿字节快照显式关闭新步骤；两组端口专项测试也关闭后续联合布线，以继续独立检验原有端口策略。新默认策略的收益、拒绝恢复、改名、条件、未知边界、状态和反馈保护、折叠与保存重渲染由新测试直接覆盖。

`check_coupled_routes.py` 独立检查 46 张实际 SVG：交叉、无关接触、共线路径、正交性、真实节点/无关模块主体侵入、标题通行、具体端口、canonical 绑定、全部 accounting 和直接表达目标。主图与陌生图的交叉改善由实际 XML 重算得到。三张浏览器审核页共检查 14 个通用 SVG 的文字边界及参考图中具有节点标记的元素，540 个形状、973 个文字对象，未发现越界；截图保存在同一目录。

源码展开检查恢复 3371 个节点和 3663 条边，每个 canonical ID 仍可见，IR 不变。此项是源码投影检查，没有运行数千节点全图 SVG 路由，也没有测量其浏览器性能。本轮未重新进行编辑器 UI 导入导出。
