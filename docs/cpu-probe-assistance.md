# CPU 探针辅助确认

通用原生画布新增 **使用 CPU 探针进行辅助确认**。对当前原始源码 IR 显式运行声明的输入，在既有 Bubblewrap CPU 隔离中采集模块类型、调用、ATen 算子、张量生产/消费和条件结果；运行证据与源码事实分开保留。所有模型共用同一入口，没有外部模型专用判断或输入猜测。

## 使用

1. 启动本机源码服务：`python3 tools/serve_semantic_studio.py`（默认 8767）。8766 的静态页面会自动使用该服务；也可直接访问 8767 的页面。
2. 在 `yworks_edge_router_lab/index.html` 打开原始源码 IR，点击 **使用 CPU 探针进行辅助确认**。
3. 指定已有 Python 环境的解释器和原始项目源码根目录。窗口显示绑定的入口文件、类和构造参数；这些参数必须与静态 IR 一致。
4. 填写或读取 `semantic-inputs/1` JSON，声明每个输入和 `eval/train` 模式，然后点击 **运行 CPU 探针**。不会自动执行、安装依赖、下载权重或生成样例。
5. 查看结果、失败原因、完整运行凭据和覆盖范围。可以下载或复制补证 IR；有轨迹时可点击 **载入补证并重新排布**。载入保留当前语义切面并切换至合并证据，重新生成几何，可通过撤销返回原图。

输入规格示例（形状与参数名需要由用户按模型填写；不是通用推断值）：

```json
{
  "schema": "semantic-inputs/1",
  "constructor": {},
  "modes": ["eval"],
  "cases": [
    {
      "id": "sample-1",
      "inputs": {
        "x": {"shape": [1, 4], "dtype": "float32", "fill": "ones"},
        "positive": {"value": true}
      }
    }
  ]
}
```

窗口初始 inputs 为空，必须填写后才能运行。输入名需要匹配实际模型接口，构造参数只支持已有探针的 JSON 参数方式；复杂对象注入不会被自动构造。

## 事实与证据

- 运行前后核对静态 IR 的全部来源文件，包括已展开的跨文件 helper；源码缺失、变化、超出源码根范围、构造配置不匹配时不附加结果。
- 新 `probe_assistance` 摘要记录原 IR 摘要、静态事实摘要、每次运行结果及未知边界的源码行关联。合并前后静态事实摘要必须相同。
- 原始 opaque 节点与精确操作数绑定保留。节点检查器新增 **CPU 辅助确认记录**，显示关联运行的算子、输入案例和模式。源码行关联不是对象身份或算子等价证明，同一行可能对应多个算子。
- 未关联到算子不代表代码没有执行，例如普通 Python 属性读取可能没有张量算子事件。
- 具体输入运行、回放一致和命中两个分支结果，不构成任意输入或所有路径覆盖证明。运行失败、截断、未执行路径以及静态未知边界仍会显示。
- 环境/隔离不可用时保留原画布，显示原因；不退回普通子进程执行模型。部分失败但有轨迹时可查看或载入该次不完整证据。

目前要求原始 `.py` 的模型类入口，以及具有 CPU、train/eval、模块枚举接口的 PyTorch 模型。工厂入口、笔记本、编辑后的合成结构暂不可直接运行。已经包含运行凭据的 IR 不能再次直接叠加探针；重新运行需打开原始源码 IR，避免证据重复。源码来源位置需要在本机可访问；导入另一台机器产生的 IR 不自动改写路径。

## 实现与验证

- `semantic_adapter/probe_assistance.py`：检查原始事实及来源，调用既有探针，合并独立证据并生成边界摘要。
- `tools/serve_semantic_studio.py`：`POST /api/authoring/probe`，要求 `execute: true`；同时最多一个探针请求，保留来源检查和隔离执行。
- `yworks_edge_router_lab/generic-probe.js`：配置、运行、结果、IR 保存与载入窗口。
- `generic-controls.js` / `app.js`：通用入口、节点证据、可撤销载入及证据摘要更新。未替换路由器或语义投影规则。
- 独立动态分派样例：`tests/semantic_fixtures/probe_dynamic.py`。通过 `getattr` 获得模块后调用，静态边界保留，实际运行确认其内部算子。
- 可复现捕获：`python3 tools/capture_probe_assistance.py --interpreter /path/to/env/bin/python`，结果位于 `verification/cpu-assistance/current/`。捕获期间记录并检查实现摘要。

独立样例的两组显式输入分别使用 eval/train，共四次真实 CPU 运行；每次记录三个算子、两个模块调用，并通过输出重放。原有两个 opaque 都保留，其中一个有源码行关联的运行算子。源码、运行与合并三种投影的连接检查和完整 IR 保存往返通过。

最终全量回归为 **109 组、1232 项**，其中 Python 168 项；全部命令通过。源码/CPU/合并模式分别检查中间切面与全部展开，共六个状态，均无无效连接，完整 IR 与几何保存重开一致。源码全部展开 13/12、CPU 轨迹全部展开 41/24、合并全部展开 54/36（节点/边）。浏览器实际验证配置、输入规格导入、运行、载入、撤销/重做、未知节点记录、CPU 轨迹展开及补证重新导入。

内嵌浏览器未报告 Blob 下载完成事件，因此未将按钮点击视为文件已落盘的证据；补证 IR 的只读文本已经读取保存，并完成重新导入。相关材料位于 `browser-assisted.json`、`browser-roundtrip.json`、`browser-node-inspector.txt`、`native-integration.json` 和 `regression/test-report.json`。

ACT 仍是外部黑箱输入，本轮没有修改、包装或运行 ACT，也未为其添加专用规则。功能的成功验证使用独立动态分派样例，不能据此声称 ACT 已完整解析。
