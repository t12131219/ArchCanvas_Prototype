# 折叠主图下面的局部细节备选

本阶段补齐通用图的细节入口：主图可以保留合适的语义折叠，而一个整块详图因过大被拒绝、或只表达部分角色时，仍能进入较小的原始源码范围、局部关系和单次调用。它不替代主图的模块逻辑及视觉收敛，也不将专用 Transformer 的展开图作为通用展开下限。

`semantic_studio/diagram-set.js` 升至 `diagram-set/2`。规划不再只依赖当前画面中折叠的外框，还可以对其下面的原始 source-function/source-module 范围提供独立入口。候选记录当前主图的真实可见锚点和原始范围，不能用相似实例代替。隐藏范围不会挤掉已有的独立局部关系入口。

整块候选仍可先试画；同一细节目标同时保留较小备选。全部模块或角色没有通过质量检查，不意味着其独立成立的已知关系也无法展示。已完成的目标不重复占用图面；失败和预算截断均保留为 deferred。候选被规划不等于已通过审核或获得覆盖。

新增局部候选检查展示祖先和原始源码祖先两条路径，也检查绑定经过的别名及边端点。条件、重复、迭代、可变操作、身份和观测边界不会因展示重排而消失。未知叶调用可展示真实接口，不授权展开未知内部。已有认证关系只在其证据范围内使用，不补成完整模型。生产规则不依据模型名称、类名、案例 ID、源码哈希或参考坐标选择。

编辑器一次展示六个候选，通过“更多详图”继续列出后续入口。用户可打开嵌套 helper、已证明的关系或单次调用，保存后重开，并返回原主图。候选按钮本身不表示该图已通过质量审核。CLI 仍由实际渲染后的尺寸、路径、文字和新增直接表达目标决定是否收入图组。

## 当前测量

冻结基线是提交 `7454852d977c3bda910f4bbfd08fa2458111675f` 的全部 23 个生产 JavaScript 文件，逐字节核对 Git。新旧使用同一 IR、同一主图状态及相同图面/试画上限。表中的分母是逐实例直接细节目标数量，不是架构语义覆盖率。

| 输入 | 原图组 → 当前直接表达 | 图面数 |
|---|---:|---:|
| NestedWorkshop | 4 → 10 / 28 | 1 → 5 |
| BrokenWorkshop | 4 → 10 / 27 | 1 → 5 |
| ConditionalWorkshop | 11 → 11 / 28 | 2 → 2 |
| LongCurve（600px 高度上限） | 3 → 7 / 17 | 1 → 5 |
| RefactoredCurve（嵌套 helper） | 4 → 18 / 18 | 2 → 3 |
| FiberBlend | 22 → 23 / 25 | 3 → 4 |
| Transformer-fixed | 60 → 60 / 1855 | 4 → 4 |

增加的直接表达使用额外图面。七个输入的主图 SVG 均与基线逐字节相同。固定粒度 Transformer 主图仍为 86 图元、94 边、2230 × 3776px、47 交叉；其三个局部角色详图也没有因本阶段获得更多覆盖。此结果不能证明与专用 Transformer 的视觉收敛。

NestedWorkshop 将长数值路径、门控、共享结果、多结果选择和未知调用放进一个 helper。BrokenWorkshop 把门控权重改为未知来源：完整门控解释消失，独立的选择、结果使用和未知接口仍可查看。ConditionalWorkshop 保留受保护的条件内部，本阶段没有增加其细节覆盖。三个新模型均仅静态抽取，未执行源码。

当前完整测试为 569 项，含 10 项新增回归。42 张实际 SVG 的几何、原始绑定、切边及逐对象去向通过独立审核；另用 Python 从原始 IR 和实际 SVG 重新计算图组分配。浏览器测量了 912 处节点文字和 94 处连线标签，未发现越界。

真实编辑器验证两条路径：`6 主图 → 7 门控详图 → 保存重开 7 → 返回 6`，以及通过“更多详图”的 `6 主图 → 15 嵌套 helper → 返回 6`。重开和返回 SVG 与原图逐字节相同；三种实际 UI 导出均与独立 CLI 渲染相同，原始 IR 保留。页面缩放后的文字可读性仍须另外判断，原生字号通过不代表任意缩放均可读。

## 复现与审核

```sh
python3 tools/extract_detail_alternatives.py
python3 tools/run_local_tests.py
node tools/audit_detail_alternatives.cjs
python3 tools/check_detail_alternatives.py
python3 tools/build_detail_alternatives_review.py
node tools/audit_detail_alternatives_ui.cjs
python3 tools/summarize_publication_checks.py
```

产物在 `verification/detail-alternatives/experiment/`。`review.html` 展示实际图面，`text-qa.html` 用于浏览器原生文字检查。UI 审核前需要在实际编辑器导入 `ui-import.json`，完成上述操作并导出对应 SVG/图文档；浏览器测量和截图不能由工具伪造。忽略的 `.layout.json` 可由渲染命令重新生成，实际 UI 保存文档保留在 Git 中。
