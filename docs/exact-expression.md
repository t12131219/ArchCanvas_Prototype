# 精确操作数审核与原子细节展开

通用语义折叠保留原始事实，但“事实仍在 IR 中”和“当前图已经直接表达该计算”需要分别审核。之前底层表达记录检查节点与边 ID，图组计分另行检查真实绑定，两处标准不一致，可能让局部规划器误以为某项计算已经表达而漏掉细节入口。

现在底层记录、角色路径、局部候选选择和图组覆盖共用精确契约：实际路由必须对应 canonical 来源、结果槽、目标操作数、边种类、条件和证据。计算节点还必须保留全部传入 flow 绑定。只有无条件的接口及别名路径允许透明追溯，条件汇合不能被当成透明连接。

显式选择单个操作的详图时，原先作为附注的形状、配置输入会成为真实边界端口；外部生产者仍留在局部范围之外。主图摘要继续采用原有配置展示策略。该规则按操作和切边触发，不依赖模型名称、案例 ID、源码哈希或参考坐标。

## 实际结果

- 八组前后对照纠正了 6 处乐观的“已表达”记录，几何与精确直接覆盖保留。
- MixedWeave、InterruptedMixer、SameSource 各新增一个此前被抑制的候选，实际原子详图各直接表达 1 个操作目标，保留 size → sqrt → div 的切边。
- 两个条件未知案例仍不满足完整绑定目标，保持未完成状态；不能为了提高覆盖而跨越条件拼接证据。
- Transformer 固定一张主图、两张详图的直接目标仍为 74，原有目标全部保留。相对冻结历史图组仍缺少 8 个历史目标、新增 33 个，本轮没有改善其几何或增加直接覆盖。
- 两次进一步展开因重叠、接触及交叉代价被拒绝，失败 SVG 保留用于后续布局改进。

## 验证与复现

完整测试 57 组、693 项通过；新增 9 项精确绑定测试覆盖遗漏操作数、错误端口/槽/条件/证据、合绘、循环、陈旧计分、陌生结构及原子输入恢复。

```bash
python3 tools/freeze_exact_expression.py
node tools/audit_exact_expression.cjs
node tools/audit_exact_expression.cjs --large
node tools/audit_exact_recovery.cjs
python3 tools/check_exact_expression.py
python3 tools/build_exact_expression_review.py
```

产物位于 `verification/exact-expression/current/`。独立审核覆盖 23 张实际 SVG，核对绑定、条件、切边、角色、几何和覆盖，两个失败候选单独记录，未算入交付图组。浏览器对 23 张图测量节点文字和端口文字边界，未发现越界；此项不替代连线质量审核。

实际编辑器已导入 SameSource 原子详图，显示 4 图元、2 连线；使用应用提供的可见导出文本保存 SVG 和图文档，重开后再次导出。`tools/check_exact_expression_ui.py` 核对保存 IR 未变、物理图形与正式 SVG 一致、重开前后 SVG 字节一致。浏览器下载等待未成功，因此此处验证的是应用导出文本路径，不宣称下载链路验证通过，也不代表 Transformer 编辑器交互已验证。

最细源码投影仍能恢复 3371 节点、3663 边，全部 canonical ID 保留。数千节点整图的 SVG 路由及浏览器性能、与专用参考的全面逻辑和视觉接近仍未完成。
