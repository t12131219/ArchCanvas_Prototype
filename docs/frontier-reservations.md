# 可逆语义视图与稳定细节前沿

目标是在不可变的原始事实图上，选择一个模块逻辑和视觉组织清楚的语义状态。专用 Transformer `01093cc06a87b35a` 的完全展开图是评价参考；它对应通用图的某个中间状态，不能成为通用图的最细粒度上限。生产规则不得根据模型名、案例 ID、源码散列或 Transformer 专用模板选择行为。

## 折叠与展开的含义

可以从最细图理解逐步折叠，也可以直接打开一个保存的语义状态。渲染时不必先绘制几千个节点：根据原始 IR、语义事实和局部展开选择，直接投影当前视图。摘要保留成员及真实边界映射，进一步展开时恢复对应细节，不需要从摘要文字反推源码。

| 视图粒度 | 作用 |
|---|---|
| 总览 | 输入输出、主要阶段和重要跨区域依赖 |
| 语义状态 | 已证明的模块、角色、旁路、来源及重复关系；与专用架构图比较的目标状态 |
| 局部计算细节 | 展开某个模块或关系的算子、操作数和依赖路径 |
| 原始源码细节 | 查看抽取到的最细源码节点、调用、值和绑定 |

这些是阅读粒度的说明，不是四个强制统一深度。同一画面可以在一个区域保留摘要，在另一区域展开具体操作。语义关系也可能跨越源码容器，不能只按类和函数边框折叠。`source/runtime/merged` 是证据选择，与粒度独立：更细的源码展开不会凭空产生运行记录。

可以把目标理解为“最细事实图 ⇄ 局部计算细节 ⇄ 语义架构状态 ⇄ 总览”。与专用图完全展开状态对照的是其中的语义架构状态；该状态之下仍有细节。这里的双向关系描述信息保留和展示选择，不要求每次运行先生成最细 SVG。实现还需要依据局部计算关系选择语义边界、映射真实端口，并重新布局，不能只沿源码函数树逐层隐藏节点。某个模块可以继续展开，而其他模块保持摘要。

当前 `source-expandability.json` 验证 Transformer 原始源码投影的 **3371 节点 / 3663 边**全部可见且 canonical IR 未改变。这证明抽取结果可以恢复；不证明任意 Python 行为都已解析，不证明几千节点同时 SVG 路由和浏览器交互性能已经达标。未知、条件、状态和对象身份边界必须继续保留。

## 本次改动

先在未降低摘要的逻辑图上分配自动展开前沿，再把符合证据条件的局部范围降低为摘要。摘要省出的节点名额不再自动展开无关区域。`publication.frontier_reservations` 记录计划展开、实际选择及互不重叠的摘要范围。手工状态、显式角色/关系请求和局部关系面板保留其原有展开契约。

同一结果被多处使用现在可以独立申请局部细节。表达目标要求真实生产者、全部消费操作及所有原始操作数路径同时成立；结构相似不能转移具体结果身份，也不宣称分支并发。自适应选择仍需实际渲染和测量：收益不足、面积过大或几何退化的候选会被拒绝。

本次规则依赖局部事实、前沿预算和实际布局成本，不识别整个模型家族。陌生组合、未知边界、嵌套摘要和重复实例共同构成回归集。
