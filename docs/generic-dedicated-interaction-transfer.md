# 专用画布交互向通用语义层迁移（2026-10-25）

本轮以 `yworks_edge_router_lab/index.html?case=01093cc06a87b35a` 的实际实现为参照，把拖动、端口、展开、DOM 复用和保存机制迁移到共用通用画布。保留此前的专用节点样式迁移和灰色无底板小字。生产选择条件不包含案例 ID、模型名、源码哈希或专用坐标。

## 参照来源与阅读范围

相邻 `../yworks_edge_router_lab/README.md` 明确说明这是参考 yWorks 公开 Edge Router 示例的行为复刻，不依赖 yFiles 运行库，也不保证商业求解器的逐点结果。Summary_Merge 内的专用版本继续加入了源码绑定、递归图、通道和质量检查。README 的部分历史描述（如裁短线尾）不代表现行代码：现行 `graph-engine.js` 的 `crop()` 保留端点，`arrow()` 在最终端点画独立的 9×8 箭头。

本轮核对了专用入口、样式、`app.js`、`graph-engine.js`、`recursive-graph.js`、`router.js`、`semantic-constraints.js`、`physical-ports.js`、`source-contracts.js`、`route-labels.js`、`junction-markers.js`、`runtime-layout.js`、后台 worker、递归存储和交互模式，以及生成端 `snapshots/transformer_programmatic_guide/draw_transformer.py`。没有将相邻实验目录的历史说明代替当前专用画布源码。

## 功能对应与迁移结果

| 功能 | 专用实现的关键行为 | 通用实现与本轮改动 |
|---|---|---|
| 图形与标题 | 原生 SVG 分层，标题是人工编写的短角色名，文字有真实包围盒 | 继续共用 `publication-renderer.js` 的节点样式、认证角色标题和完整 tooltip；不凭名称把陌生程序改写成已知算法 |
| 标题区域移动 | 父框保留 2px 边界，不把整行标题当作节点禁区 | `canvas-interaction.js` 的拖动和保存恢复使用相同父框边界；允许内部节点与标题同行或覆盖标题 |
| 大父模块碰撞检查 | 从不可变起点移动整棵可见子树 | 新增包围关系的快速检查：根框完整包围子树时先查根框；仅对原有交叠障碍逐个检查子节点；子树越出根框时退回一般算法 |
| 拖动帧 | RAF 合并事件，内部线整体平移，边界线做轻量预览 | 新共用 `canvas-preview.js`；把同一层连续的移动图元包成临时组，每帧更新组变换，边界路径引用只查找一次；视图和编辑模式共用 |
| 层叠与取消 | 预览不改变语义，取消恢复原图 | 只合并连续兄弟，不跨过静止图元；取消时解包，恢复原顺序、原始路径和可见性；释放后保留预览至后台事务完成 |
| 直线端点 | 预览要保留固定端和箭头方向 | 修复原通用两点直线预览会丢失固定端点的问题；两端均有测试，保持正交和箭头进入方向 |
| 箭头样式 | 9×8，箭尖与物理端点重合 | 视图和编辑模式使用相同世界单位尺寸、`refX=9/refY=4`；随线色变化，不随合绘线宽膨胀；规范线路不裁短 |
| 释放后布线 | 后台求解、物理端点可调整、失败回退 | 只在释放后搜索普通连接的四侧组合，最多求解四个有希望的侧组合；比较实际路径长度与折点。改变一条边的端口侧后，检查同节点其他边的端点，避免旧线错挂 |
| 约束端口 | 普通端点和真实固定接口分开 | 控制、展开边界、认证旁路、上下文通道、跨区策略、条件、迭代与合绘等继续使用既有策略；物理侧策略独立保存，重开校验边身份、合法侧、精确端点和避障 |
| 父模块展开 | 驻留完整模型、复用可见状态和合法旧线 | 视图原有架构增量路径继续保留；编辑模式不再每次展开都重新初始化 worker，新增原子/源码依赖画布的增量路径；不满足准入条件时使用完整计算 |
| 展开按钮 | 展开/收起控件应有独立命中范围 | 两种模式都添加 28×28 世界单位的透明点击区，支持 Enter / Space，阻止误触父模块拖动 |
| 编辑 DOM | 保留节点/边实例，避免频繁重建 | 编辑模式复用节点和边的外层实例，按内容更新内部绘制；去掉节点归属/子节点存在判断的重复线性扫描 |
| 编辑连接手柄 | 按规范绑定找到实际边 | 新增一轮构建的端口索引与规范端点映射，替代每个手柄搜索整图；保持接口名称、次序和精确操作数 |
| 移动保存 | 几何和原始事实分开保存 | 修复编辑模式把移动结果误存为旧 `offsets` 的问题；现在保存完整 `canvasPlacement`，传回 worker 校验，文档导入也能恢复 |
| 撤销/重做 | 旧图保持到完整候选提交 | 保留驻留场景缓存与事务检查；视图/编辑模式的原始事实、调用身份、参数共享及继续展开入口均不被预览重写 |

没有照搬专用 `runtime-layout.js` 中的固定运行节点、泳道坐标，也没有把专用人工短标题当作通用算法识别器。自动布局仍保留默认标题留白；本轮解除的是手动移动整行禁区，不会默认把所有子节点压到标题上。

通用路由仍以现有正交求解器为基础。四侧候选不等于穷举周长上所有比例，也未复制专用的曲线/八方向工具。物理端口仍按真实独立绑定分配，不合并不同操作数。图例中的源码/运行/控制证据区别继续保留。

## 代码关系

- `semantic_studio/canvas-interaction.js`：子树会话、边界/碰撞、无求解预览、释放事务、物理侧提案、保存恢复。
- `semantic_studio/canvas-preview.js`：只负责 DOM 预览、连续组、边界线引用和准确清理；不读写 IR。
- `semantic_studio/architecture-layout.js`：共用端点分配和正交布线，物理侧策略覆盖只对允许的连接生效。
- `semantic_studio/publication-renderer.js`：统一箭头、架构和 canonical 依赖画布的父展开复用与质量准入。
- `semantic_studio/app.js`：视图模式使用共用预览，在守卫提交时再清理临时组。
- `semantic_studio/authoring-app.js`：编辑模式的驻留场景、DOM 复用、预览、端口索引、完整几何保存。
- `semantic_studio/authoring-model.js`：快照级端口索引；各节点原接口返回顺序与旧实现精确一致。
- 两个 HTML 入口和 worker/client 依赖版本一起更新，避免只刷新主页面却继续使用旧 worker。

## 浏览器实测与自查

使用 CUA 操作实际专用参照页和通用产品页，未通过脚本调用业务方法伪造指针操作。最终版本为 `dedicated-interaction-3`，见 [最终架构详图截图](../verification/dedicated-interaction/current/final-architecture.jpg)：

- 专用页执行收起/展开，核对后台校验、端口策略和当前实际递归结果。
- 通用 F1 拖动 `self.decode`：90 个需平移图元组成 17 个连续组，只预览 6 条边界线。9 次预览采样的中位约 0.20 ms、最大约 2.30 ms；释放后台计算 248 ms，端到端约 464 ms。提交时 80 节点、80 边实例全部复用，临时组数量归零。采样较少，不作为帧率保证。
- 编辑模式实际展开非根 `self.decode`：最终版本后台计算 140 ms，走增量路径，复用原有 27 节点 / 24 边，仅新建 10 节点 / 9 边。实际鼠标收起以及 Enter / Space 操作均验证状态变化；收起和再次展开命中驻留缓存，后台计算为 0 ms（不代表端到端零耗时）。透明命中区随画布缩放，并非屏幕固定 28 px；极小缩放下仍建议先放大或用键盘。
- 浏览器从 F1 实际展开到 3371 节点 / 3663 连接；后台准备 10336 ms、DOM 更新 435.10 ms、端到端 11142.30 ms，仍报告待调整路径。
- F1 保存的图文档仍含 3371 个原始节点和 3663 条原始边；实际执行撤销/重做，撤销命中驻留缓存。
- 普通 MLP 编辑画布实际将输入节点由 y=130 移至 y=32.714681440443215，父框 y=30，进入其标题行；释放通过路径校验，19 节点和 18 条边全部复用。
- 编辑文档包含完整 `canvasPlacement`；实际撤销回到 y=130，再经文本导入保存的文档，恢复 y=32.714681440443215。见 [标题行移动截图](../verification/dedicated-interaction/current/editor-title-row.jpg)。截图有意展示手动覆盖标题，并不代表默认自动布局。

审查时修复了三个容易被表面顺滑掩盖的问题：旧直线预览会丢固定端点；编辑移动没有保存真正的几何；随意跨过静止图元合组会改变 SVG 层叠顺序。本轮分别用端点断言、实际文档导入和连续组/取消恢复校验约束。

完全展开初始准备、复杂陌生图的布局质量及大范围释放后的全图校验仍有成本。本轮降低了拖动帧与端口枚举负载，并扩大了安全展开复用范围，没有将数千节点的全量准备描述成瞬时完成，也没有移除原有路由失败的可见报告。
