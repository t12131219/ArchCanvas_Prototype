# 多次使用的源码输入：在原作用域内测量位置

本轮将共享输入摆放提炼为通用绘图规则。Transformer 只是双状态的参照案例，生产选择器不读取模型名称、家族标签、案例 ID、源码哈希或专用图坐标。规则可以用于线性、卷积、分支等不同语义的图；是否采用由已有输入身份、实际可见使用、所属作用域与整图测量决定。泛化不意味着强迫所有语义采用同一种布局。

## 做了什么

先完成已有的语义折叠、模块编排、短路径行布局和独立入口区域高度选择，再尝试移动被多处使用的源码输入。输入仍属于原来的绘图父框，只利用已经存在的空闲区域；不移动其他节点，不增加折叠，不删除运算。每次使用的原始源、目标和操作数槽位继续保留。物理端口朝向可以随位置变化，但不替换规范端口身份，也不把输入改称为某种算法角色。

候选必须是没有可见上游写入、至少有两条实际可见使用的输入接口；调用绑定接口、条件、可变、对象身份、运行观测、仅运行时证据及控制/状态/未知节点不参与。使用边必须为普通数据、别名或接口绑定，反馈和特殊布局通道不参与。原作用域的保护边界也继续保留。

在可见展开兄弟框的上下方及消费者的中间高度生成候选，按实际消费者距离排序，检查原父框内的包含关系及与其他节点的空隙。每图最多处理三个输入，每个输入最多测量三个位置；超过 128 条可见边、已有未解决路由或标签问题的图保持原策略。手工位移及显式 `paperArchitectureInputs: false` 跳过该过程。打印视图不使用本规则。最多九次整图路由测量会增加复杂切面的渲染开销；本轮未建立交互时延基准，可用显式退出保留原策略。

每个候选重算完整路由，并重新检查实际路径与实体障碍。局部保留旧路线可能忽略目标端口重新分配，因此不能作为采用依据。连线允许穿越已展开模块的标题区域，实体节点内部仍是障碍。

## 采用条件

候选必须保留相同的可见节点、所有精确绑定、完整节点/边归属、已满足的直接表达目标和摘要目标、已应用约束与已实现关系。整图逐边总线长必须严格减少，画布宽高不能增加，字号不能缩小，交叉、不相关接触、不相关重叠、路由和标签问题都不能增加。更短但增加交叉的方案会被拒绝。所有尝试与最终采用的位置都保存在 `architecture_input_placement` 收据中。

模块列、短路径与自然高度的内部比较暂时跳过最后这个输入位置阶段，避免相互递归搜索。最终确定的布局再执行一次有界位置搜索。基础语义 IR 和各层展开关系没有改变。

## 验证与复现

全量回归 95 组、1083 项通过，其中架构编排 44 项。正式 106 个状态中有 18 个 SVG 改变，包含普通读取、独立和并行模块、空间流水线及新增共享输入源码。定向测试覆盖普通共享输入的采用和拒绝、标签与来源重命名、身份/可变/条件/运行证据边界、单次使用、手工位移、显式退出及保存重开。独立审计从实际 SVG 与保存文档检查路径、实体接触、文字边界、全部规范绑定、目标覆盖和非输入节点位置不变。

复现先将 `fc24712` 的 `semantic_studio` 用 Git archive 解包至 `/tmp/archcanvas-input-placement-fc24712`，然后运行：

```
node tools/capture_input_placement.cjs
python3 tools/build_input_placement_review.py
python3 tools/check_input_placement.py --geometry-only
python3 tools/run_local_tests.py
```

浏览器原生测量覆盖 106 张 SVG、1464 个可见图元，未发现文字越界。实际编辑器完成 Transformer 的 28/37 概览 → 80/80 详图 → 82/81 继续展开 → 保存 → 返回 28/37 → 重开 82/81；保存文档保留规范 IR 的 3371 个节点、3663 条边与原概览快照。普通共享输入、卷积/线性双路及空间流水线的细节与返回状态也实际导出，均与正式 SVG 逐字节核对。

完整 `python3 tools/check_input_placement.py` 需要上述实际浏览器文字测量和 UI 导出。大型布局 JSON 留在本地；输入、SVG、精简报告、截图与复现工具纳入仓库。
