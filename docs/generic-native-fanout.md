# 原生通用画布：同值分支和并行模块换序

日期：2026-10-26。接续 `generic-native-flow.md`；本轮开始时保留该轮全部未提交改动，没有执行 Git push。修改前的原生画布、测试、文档及捕获工具备份在 `/tmp/archcanvas-fanout-20261026/before-code.tar`，修改前三份 SVG 和审核报告在同目录 `before/`。

## 使用范围与事实边界

新增 `yworks_edge_router_lab/flow-optimizer.js`，所有通用模型和导入的源码 IR 经过相同规则。生产代码不匹配 Transformer、Q/K/V、模型 ID、源码哈希或专用坐标。

布局换序只更改节点横坐标，携带可见后代；节点 ID、调用身份、源码归属、纵向数据层次、操作数槽、原始边和完整 IR 均保持不变。F0/F1 和局部继续展开仍采用原有可逆语义切面。分叉圆点是当前路线的绘图标记，不是新增计算节点、源程序事实或必须锁定的布线骨架。

## 同一个值的共享线干

按可见生产者、已认证 `contract.wire` 和精确输出槽共同分组。规范值的身份仍由通用语义适配器核验；几何接近、名字相似、共享模块对象都不能证明输出值相同。不同调用、不同输出槽、合绘边、条件或未知关系、状态修改、视觉草稿和手动途经点不会被强制合并。

先尝试整个分支组的联合候选，避免逐条修改时新旧线干暂时重复而错失共享方案；再尝试单条分支复用已合法的路线前缀。候选联合选择同一生产者端口、真实分叉位置和各消费端的物理端口，保留每一条精确依赖。

对同一值、同一水平或垂直坐标上的线段求区间并集，得到实际绘制的线干总长 `ink`。原来的路径总长仍逐消费者累计，因此共享之后这个数可能略增。候选要求 `ink` 减少、交叉不增加、每次事务累计路径长度最多增加 4%、折点最多增加 1，并且 `ink + 40 × 折点 + 450 × 交叉` 降低。所有物理端口、箭头末端、节点障碍和源码边界穿越顺序仍须合法。这个权衡不等于所有视觉指标同时改善；报告同时保留贴边惩罚等指标供审查。

分叉点只出现在同值路线的共同前缀末端且存在至少三个方向时。它们从当前路线即时推导，拖动预览、提交、撤销、保存重开和 SVG 导出都使用实际几何；原本已共享的合法路线也能显示分叉点。不会在无关线的交叉处画连接点。

## 并行模块的位置换序

从同一父模块、同一纵向层次的 2–4 个节点提出排列候选。检查提升到兄弟层次的全部依赖，存在直接或间接先后关系时不换序。状态、迭代、未知、条件摘要、重复调用摘要、身份展示和敏感后代采用保守限制。

候选先按真实输入、输出的横向距离和同值消费者是否相邻排序，每行至多实际布线比较两个排列。没有固定的 Q/K/V 角色顺序；两个分支共用一个输入、另一个输入独立时，可以得到 K/V/Q，也可以保留原顺序。

换序时先随节点转移旧路线的端点和末端折点：完整移动的内部线路整体平移，仍然合法的通道复用。消费端没有随之移动的输出线会重新选择连接侧和连接点；被新图元阻挡的其他线路也进入局部重算。随后尝试同值共享分支。

事务最终执行源码、归属、不重叠、端口及所有路径检查。路径总长、折点、交叉和 `ink` 都不增加，并且至少一个相关指标改善才采用；未完成预算或任一检查失败时保留原图。换序不修改图数组顺序、源码操作数或真实调用先后。

## 交互、预算与兼容

新增搜索只用于不超过 300 个可见节点和 300 条连接的正交切面，每个分支组 2–12 条边。首次布局的换序预算默认 2200ms，分支优化 600ms；预算为协作式检查，并非硬实时期限。数千节点的源码视图继续沿用原有分批布线，不进入这次搜索。曲线和八方向模式保留既有路由方式，避免在曲线圆角之外绘制虚假的直角分叉点。

拖动时不执行模块换序；释放及 Apply 只对限定的连接尝试 100ms 分支优化，未选中边、手动折点和 Never 策略受到保护。语义事实缓存、证据传输缓存和完整 IR 保存机制不变。

renderer 更新为 `native-semantic/12`，文档 schema 仍为 `archcanvas-native-semantic/1`。renderer 1–11 的旧布局与保存状态保留在迁移来源中，并按当前规则重建图面；12 的布局按当前保存结果恢复，圆点根据恢复的路线重新推导。
