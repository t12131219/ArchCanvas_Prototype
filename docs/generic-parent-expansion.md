# 通用画布父模块展开性能

本轮参考专用编辑器 `yworks_edge_router_lab/recursive-graph.js` 的不可变层级查询、切面缓存和合法旧线路复用机制，继续优化通用语义画布。节点、模块样式及通用语义认证规则保持原有实现；默认 F0、F1 与继续展开的正式 SVG 仍逐字节核对。

## 实现边界

- `publication-renderer.js:prepareFrontier()` 只处理显式父模块展开/收起。首先从完整 IR 重新建立新切面的节点、精确操作数、调用身份、归属、条件和全部事实分区，再进行几何复用。没有模型名、案例 ID、源码哈希或专用坐标选择条件。
- 沿用此前实际选择的短路径朝向与独立输入区域高度策略。旧路径只有在新端口坐标允许整体平移、全部线段通过新障碍检查时才复用。其余路径在保留线路的环境中重新求解。
- 使用至多两个局部修复阶段，每阶段至多两轮、每轮至多四条线路、每条一个策略，继续测量真实路径、文字、端口标签、冲突和认证约束。修复在同一新切面上比较，不允许增加交叉或新增接触对。仍可表达的已兑现直接/摘要目标不得丢失。
- 不将两个不同切面的交叉绝对数直接作为准入比较：展开会引入真实依赖，并改变周围框的排布。报告保留跨切面的交叉诊断；默认正式三档的布局选择未改变。
- 有路线失败、物理障碍、未放置标签、新增不相关接触、重叠或可见约束/表达损失时，候选返回空，继续原来的完整布局和质量回退。

## 重复计算与缓存

`expression-goals.js` 在每次审核中一次建立关系收据及节点索引；`summary-goals.js` 一次建立源码和展示父子索引。它们不跨审核复用可变的认证结果。`publication.js` 的文字宽度缓存只记忆相同字符串和字号的纯计算，最多 8192 项。

`architecture-layout.js` 按固定横/纵坐标索引本条线路的保留线段，保持原来的累加顺序、端点包含规则、退化线段、代价和搜索预算。可见性搜索改用数字编码表示同一网格、方向和通道状态；堆的插入及平局顺序不变。原路由逐项对照测试继续覆盖普通、嵌套、条件、反馈、环形端点和多种拥塞策略。

`scene-runtime.js` 的六场景缓存改用最近访问顺序淘汰。展开集合按集合身份比较，导航返回快照和纯证据说明不再造成相同切面失效；模式、焦点、角色请求、方向、人工几何等仍参与键计算。响应保留本次完整导航状态。增量结果同时登记原请求与保存几何的键，撤销、返回和再次展开可命中同一场景。

## 保存与失败恢复

增量切面沿用 `semantic-canvas-placement/1`，保存全部几何和路径，以及白名单中的物理布局提示。提示不能修改证据模式、焦点、语义角色或源码绑定。CLI 导出、重开和后续移动继续验证物理路径与规范端口。端口核验只计算真实端口分配，不为每条已验证的保存线路再次执行寻路。

后台计算超时会终止旧 worker、恢复已提交场景，并为下一次操作重新初始化 worker。超时任务不会再在主线程重算。浏览器不支持 worker 等能力失败仍保留原兼容路径。

## 证据与复现

正式对照位于 `verification/parent-expansion/before/report.json` 和 `verification/parent-expansion/current/report.json`。前者使用提交 `81633d5` 的冻结源码副本。后者同时核对默认三档、普通程序和父模块完整计算的 SVG/事实摘要，并检查增量父模块的首次展开、收起及保存重开。捕获期间冻结生产代码与捕获器。

```sh
mkdir -p /tmp/archcanvas-parent-before
git archive 81633d5 semantic_studio | tar -x -C /tmp/archcanvas-parent-before
PARENT_AUDIT_SOURCE=/tmp/archcanvas-parent-before/semantic_studio \
  node tools/audit_parent_expansion.cjs verification/parent-expansion/before
node tools/audit_parent_expansion.cjs verification/parent-expansion/current verification/parent-expansion/before
python3 tools/run_local_tests.py
# 报告和对应日志归档到本阶段后执行：
node tools/check_parent_expansion.cjs /tmp/parent-incremental-document.json
```

`tests/parent-expansion.test.cjs` 另行验证普通程序和全 ID 改名程序的首次展开、切面分区、精确保存重开、缓存导航状态、缓存淘汰、模型失效、拒绝回退及超时不进入主线程。浏览器通过 CUA 操作真实控件，检查后台计算、重新展开、撤销/重做与最终图面。

增量候选不保证每个父模块均获采用；拥塞边界仍可能执行较慢的完整计算。冷启动 F1 也仍包含完整语义投影及多轮质量选择。数千节点同时可见的性能尚未验证。

## 本机测量与结果

以下为冻结版本的顺序单次测量，单位为毫秒。完整计算的五张 SVG、展示节点/边及完整事实分区与修改前相同；普通输入规模较小，其微小时间差不作普遍加速结论。

| 完整计算 | 修改前 | 当前 | 减少 |
| --- | ---: | ---: | ---: |
| F1 语义详图 | 21717.6 | 15438.2 | 28.9% |
| F0 架构概览 | 6562.9 | 4320.9 | 34.2% |
| 继续展开 | 19364.4 | 12492.0 | 35.5% |
| decoder 收起后完整计算 | 7572.8 | 4826.4 | 36.3% |
| 普通共享输入程序 | 20.0 | 16.6 | — |

同一 decoder 父模块增量收起为 **727.9ms**，复用 26 条路径、重算 11 条；从保存的收起状态首次展开为 **804.2ms**，复用 26 条、重算 54 条；直接恢复保存几何为 **762.0ms**，SVG 精确相同。收起图为 4 个交叉，增量首次展开图为 11 个交叉，均没有未解决问题和不相关接触。默认完整 F1 仍为原来的 12 个交叉。增量几何与完整重排可以不同，自动排布可恢复完整布局。

CUA 在实际页面中测得：冷 F1 后台计算 19121ms、整次提交 19387.5ms；decoder 首次收起计算 863ms、提交 1047.3ms；回访原 F1 命中缓存，提交 201.7ms；撤销/重做分别约 186.4/195.2ms。重新导入保存文档后，恢复后台计算 3136ms、提交 3410.2ms；该文档首次展开计算 1107ms、提交 1311.2ms。浏览器恢复路径包含基线图准备、传输及 DOM 等额外工作，不能以 CLI 的 762ms 代替整次浏览器打开耗时。

普通程序通过真实父模块控件完成 18/15 → 14/12 → 18/15，采用增量及缓存。该普通程序 UI 检查与全量测试并行，其耗时只归档，不纳入性能比较。具体记录见 `verification/parent-expansion/current/ui-metrics.json`。

本轮继续明确限制：较拥塞的 encoder 父模块候选仍会拒绝，回退计算可能超过 120 秒。超时取消并保留旧场景，不再进入主线程重算。当前加速覆盖已验收的 decoder 和局部父模块，不能宣称每个父模块均同等加速。

最终冻结版本的全量 **98 组、1112 项测试通过**。`acceptance.json` 独立核对测试与捕获源码 SHA、五张完整布局的 SVG/事实摘要、正式三档 SVG、三份真实 UI 导出、完整 IR 分区、物理路径、认证冲突与精确保存恢复。浏览器长 SVG 通过分段读取完整导出后比对，未使用截断文本作为通过证据。页面截图为 `final-ui.png`，增量首次展开截图为 `opened-ui.png`。
