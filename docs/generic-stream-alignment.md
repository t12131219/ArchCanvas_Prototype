# 通用输入流几何对齐

本轮提炼人工架构图中的“入口基线与出口侧核心对齐”，应用于通用绘图投影。它按实际输入、可见容器、兄弟依赖和测量尺寸触发，不读取模型名、案例 ID、源码 SHA、算法角色或专用图坐标。Transformer 只用于两档对照；新增卷积与全连接混合的 SensorFusion 源码用于跨模型正例。

## 实际改动

多条外部输入流已经并列时，较矮区域原先靠输入基线放置，导致核心整体偏低。现在将较矮区域伸展到同组最大高度，把余量放到出口侧展开核心之前。向上主流程中，两个核心顶部与原有输入基线同时对齐；向下主流程则对齐出口侧边缘。节点尺寸、源码归属、原始边及每个操作数绑定保持不变。对齐只表示绘图组织，不表示并行执行。

规则要求同一兄弟切面能形成严格有序的数据依赖走廊，并存在唯一的出口侧展开核心。已有认证的前向旁路仍属于普通数据使用，可以保留。条件、可变、未知和控制节点，非普通边、迭代、反馈、环、断开的节点和无法排序的并列分支都阻止这项伸展。它不跨过这些边界推断新语义。没有适用结构时继续采用原来的通用布局。

这项规则对所有通用语义使用同一入口和判据，并不要求所有模型都触发对齐。卷积、全连接、注意力等名称没有特殊待遇；循环和状态程序也不能为了视觉一致而丢掉其事实。

## 两档结果与代价

比较使用提交 `1426e9c` 的真实 SVG 和相同展示状态，没有重新生成“修改前”来美化收益。正式重放原有 42 张图，另加入陌生混合案例的两个方向，共 44 张 SVG。

| 展示状态 | 修改前核心顶部差 | 修改后 | 尺寸 | 交叉前 → 后 | 线长前 → 后 |
| --- | ---: | ---: | --- | --- | --- |
| Transformer 概览 | 180 px | 0 px | 1250 × 1574 | 8 → 8 | 8534.5 → 9619.5 |
| Transformer 语义详图 | 916 px | 0 px | 2506 × 3850 | 12 → 14 | 39249 → 45409 |
| SensorFusion 向上 | 268 px | 0 px | 984 × 1086 | 0 → 0 | 1501 → 1501 |

两个 Transformer 目标状态都改善了区域顶部组织，输入和预处理保持原基线。代价是概览和详图线长增加，详图多出两处交叉；这是明确的几何权衡，不能声称整体质量全面改善。整体尺寸没有缩小，专用参照的简洁程度尚未达到。源码包裹、重复后续调用卡片、条件内部和残差/上下文线路仍是后续问题。

## 验证

- 全量 95 组、1048 项测试通过；架构编排 17 项，新增覆盖两个方向、名称扰动及上述拒绝边界。
- 44 张 SVG 逐项比对节点集合、边绑定、节点与边归属分区，保持与修改前一致。独立审核检查角色路径成员、源码摘要、正常返回、物理绑定、正交路径、接触、重叠、节点障碍和允许的标题穿越。
- 浏览器原生测量全部 44 张 SVG 的非空卡片文字，未发现越界。
- 实际界面完成 `28/37 → 80/80 → 82/81 → 保存 → 28/37 → 重开 82/81 → 28/37`。各档、重开和返回导出与正式 SVG 字节一致；陌生混合模型实际导出也一致。
- 保存文档完整保留 Transformer 的 3371 节点、3663 边。巨型全部展开 SVG 性能仍未验收。

审核脚本首次按标签查找输入时，误取了不可见帮助函数中同名的输入。修正为先按可见节点身份筛选，再核对实际几何；最终审核全部通过。这是审核器的身份选择问题，没有修改输入事实来绕过检查。
