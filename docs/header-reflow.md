# 展开外框按实际宽度重排完整标题

本轮从专用图中借鉴的通用经验是：文字应使用当前可见容器的宽度，布局不必继续为折叠节点的窄标题预留空白。展开模块标题区仍允许连线穿过；计算节点、固定参数节点和无关模块主体仍是障碍。

`publication-renderer.js` 的 `prepareHeaderReflow` 在现有联合布线之后执行。它按最终外框宽度重排已有完整标题和说明，保持字体不变，不删除调用次数、参数身份或来源说明。候选选择不检查模型名、类名、案例 ID、源码哈希或专用坐标。

该步骤只修改最终展示，不修改 canonical IR、语义前沿、模块身份、操作数、条件或源码归属。源码细节仍可展开；它不会把代表调用的结果替换成整个重复序列的最终结果。

## 边界保护

- 存在额外操作数说明、独立 inventory 行预留、固定参数栏或外框连接端点时，保留其原有布局合同，暂不重排该外框。
- 重排必须保留标题和说明的全部非空白字符，不能只用原始 caption 重建附加了证据行的文字。
- 若缩短标题区会让现有无关连线进入模块主体，保留标题区高度，仍可使用较宽的文字排布。
- 仅通过已有的全局空白带压缩器移动几何；不重新布线，不改变边的端口侧、来源、目标或槽位。真实节点保持尺寸，所有坐标使用同一个单调纵向映射。
- 保留既有表达目标、约束和已实现的关系；交叉数、线长、画布大小、接触、重叠及字号均不得退化。失败则保留基线结果。

手动位置、显式标签间距、标题强制避让、印刷模式和资源上限均跳过该步骤。`paperHeaderReflow:false` 可关闭；`diagnostics.routing.header_reflow` 记录完整文字、前后标题高度、阻止收缩的连线和实际采用的空白带。
