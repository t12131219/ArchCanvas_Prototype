# 已有详图的继续展开

图组规划不能只向主图增加细节。主图和恢复详图已经用满图数预算时，恢复图仍可能有更细的局部角色层或计算关系；规划器现在可以直接细化它，而不增加图数、不替换调用实例或改变该图的原始作用域。

`diagram-set/5` 为每次原位细化记录 `target_panel`。只有规划器生成并标为 `refinable` 的详图参与自动替换；用户固定的图不会因此被自动修改。恢复图采用显式 `open` 列表时，新增展开路径来自角色编译器或局部关系编译器的授权，保留原有展开列表，不依靠重置整个自动展开状态获得细节。

每次候选图仍须实际布局、路由和审核。规划器检查整个图组的精确操作数覆盖，拒绝丢失已直接表达目标的替换；也检查被替换图自身的角色、摘要、未知边界、切边、字号、资源和交叉代价。图 ID、入口锚点和标题保留，最终选中的状态可以保存后重新渲染。

同等预估收益下，完整角色层先于单条角色路径试验，避免标识符的字符串排序耗尽预算。完整角色层不因此获得通过资格，失败后仍可尝试部分路径。节点、条件、状态或证据边界不因这个顺序变化而消失。

## 可重现证据

```bash
node tools/audit_panel_refinement.cjs
python3 tools/check_panel_refinement.py
python3 tools/run_local_tests.py
```

正式产物位于 `verification/panel-refinement/current/`，包括输入哈希、实际 SVG、候选状态、所选图组、独立覆盖和几何检查。布局 JSON 为可重现的忽略产物，需先运行生成命令。

| 通用案例 | 原详图节点 | 新详图节点 | 图组直接目标 | 新详图交叉 |
|---|---:|---:|---:|---:|
| NestedWorkshop | 9 | 16 | 7 → 16 | 0 |
| SameSource | 10 | 16 | 7 → 11 | 0 |

两个案例都在两张图名额用满时完成原位细化，固定主图和详图原始作用域。独立 Python 审核从实际 SVG 重算精确操作数和几何，未用候选宣称代替覆盖。浏览器原生 DOM 测量检查六张前后 SVG 的 137 个节点文字块和 9 个端口文字块，未发现文字越界；截图保留在同目录。该审核不等价于 Transformer 的浏览器导出、重新打开及全部交互已验证。

Transformer 的实际试验还揭示了布局限制：一个完整嵌套角色层能够补回 8 个精确目标，但在相同原始作用域下，详图由 30 节点、16 交叉增至 43 节点、44 交叉，超过允许代价，被拒绝。

问题来自通用分支列布局排除了已展开的子容器。局部结构满足同阶依赖、独立路径和真实消费端口时，现在允许展开容器整体进入列布局，内部事实保持原样。已有的实际路由、字号、面积和线长检查继续决定是否使用该候选，不改变质量阈值。隔离试验中，同一 43 节点候选的交叉数从 44 降至 19，高度从 3718 降至 2784，达到原有局部代价检查；最终图组是否采纳仍以正式生成和独立审核为准。

`InterruptedPaths` 的显式列布局对照验证了未知调用外框也可作为一个几何容器排列：未知调用本身保持可见，14 个精确目标全部保留，未推断内部行为。该候选交叉仍为 3，线长从 3442.2 增至 4139.2，因此自动选择仍拒绝它。列布局不是始终优于普通拓扑的承诺。

本轮完整测试通过 56 组、683 项；与专用图在同一语义状态下的完整视觉和逻辑收敛仍未完成。

最终整合审核通过，检查了 112 张正式候选及编辑器产物，重放了 4 次被接受的原位替换；浏览器原生 SVG 文字测量未发现越界。Transformer 所选两张恢复详图的交叉数由本轮改动前的 16、57 降至 3、21，节点及作用域保留。这里的几何比较基线是改动前同一折叠方案，不是冻结的历史图组。

完整嵌套角色候选最终仍未选中：虽然其交叉数降至 19，但整合后的恢复图基线也降至 3，仍超过允许增量。最终图组的直接目标仍为 66，相对冻结历史图组的 49，缺少 16 个历史目标、新增 33 个。通用详图细化能力已在上述两个通用案例成立，不能据此声称 Transformer 的展示缺口全部补足。
