# 精确角色身份与上下文标题

通用语义主图需要同时保留准确的局部事实和可读的角色表达。此前单条路径请求保存了完整键数组，但角色注释、回执和自动选择的角色集合仍使用点分隔字符串。例如 `["a.b"]` 与 `["a", "b"]` 可以具有相同字符串，甚至指向同一节点，因而在后续角色集合中被合并。数字成员的图面标题也可能只显示 `0`。

现在 `role-frontier/3` 和 `role-paths/2` 在角色注释及回执中保留 `role_keys`。路径回执按准确键数组匹配；自动选择的暴露角色集合也按准确键数组区分。原有 `role` 字符串仍作为可读说明，不能作为唯一身份。回归验证移除一个带点/嵌套角色后，即使另一个角色仍指向相同节点，选择器也能发现原角色丢失。

数字成员的标题保留最近的所在字段及后续路径。例如 `stages → 12` 显示为 `stages · 12`，而非孤立的 `12`。带点的单个键不被重新解释为嵌套路径。含点或数字成员的 SVG 工具提示另列准确键数组。未知、条件、原地修改与共享身份边界仍使用其原有标题。规则不检查模型名称、案例 ID、源码哈希或特定角色名称。

八组真实源码 IR 以前一提交 `4e8c902` 冻结的实现和当前实现分别生成16张实际SVG。BoundedWeave、MixedBoundary、ConditionalWeave各有一个标题从 `0` 改为 `numerical guards · 0`；对应节点宽度184→202px，中心、纵向位置、高度及全部实际边路由不变。八组的质量指标均相同；SameSource、ConditionalCarry、SharedMismatch、BrokenCell和GatedMixture五组完整SVG逐字节相同。新增角色键字段不改变原始IR、accounting或原有角色事实。
