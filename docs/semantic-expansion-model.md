# 语义架构状态与原始细节的关系

目标是在同一份通用事实图上，形成一个模块逻辑和视觉组织尽量接近专用案例 `01093cc06a87b35a` 的中间语义状态；该状态仍能向下查看更细的实现。专用案例用于审核表达效果，不作为生产规则的模型名、案例 ID、源码哈希或固定布局模板选择条件。

## 如何理解“从最细节点折叠”

从信息保留角度，可以这样理解：最细事实仍存在，语义摘要代表其中一部分内容，展开可以返回更细的计算与来源。

实现上，系统从抽取的事实构造局部关系及候选展示区域，再选择各区域的表达和可见前沿。它无需先将数千节点全部排成 SVG，再逐个折叠。语义区域的组织也不必等同于源码类和函数的嵌套。多个关系可以重叠，主要展示容器及跨容器端口负责组织画面。

因此，细节保留、语义边界和布局是三个相互配合的工作。只把现有节点收进外框或减少节点数量，不足以获得专用图的模块逻辑和视觉组织。

## 目标状态的位置

以下是阅读层次示意，不代表目前已全部完成的五档产品功能，也不是必须全图同步切换的固定深度：

| 阅读层次 | 主要内容 |
|---|---|
| 整体概览 | 主要区域、接口和依赖 |
| 语义架构 | 有依据的模块、内部阶段、角色、旁路、重复及上下文关系 |
| 局部实现 | 某个区域的投影、轴变换、条件、辅助操作等 |
| 源码与调用证据 | 具体操作、参数与结果槽、来源及观测记录 |
| 原始事实投影 | 当前抽取器已经保留的全部节点和边 |

专用图的全展开状态，是通用图某一合适的语义前沿的参照，不是通用图最细原始投影的参照。一个画面可以同时保留模块摘要、展开某段角色关系，并继续细看另一处陌生计算。

2026-10-22 补充的第二项参照是专用图的完全折叠状态：通用图应能从上述语义前沿继续收起到保留主要子计算、旁路和跨区依赖的语义概览，再展开回来。这两档必须分别审核，不能用几乎不显示内部结构的根模块摘要代替参考中的子层骨架。具体要求见 [双语义前沿目标](semantic-frontier-targets.md)。

折叠后的摘要必须保留原始成员、边界依赖和端口绑定；不能为了外观相似而改变来源、操作数、条件、共享或状态关系。展开恢复具体内容，但不承诺折叠前后的坐标完全相同。

因此，“从最细节点开始折叠”描述的是信息之间的关系，不是用户必须执行的操作顺序。默认可以直接打开架构语义状态，再只展开感兴趣的区域；也可以切到源码视图检查原始事实。专用图的全展开应与通用图的目标中间状态比较，两者不要求节点一一对应或数量相等。

`source / runtime / merged` 选择的是证据范围，不是从粗到细的三个层次。同一范围内才选择摘要与展开状态。当前 3371 / 3663 的恢复检查针对本次保存输入的源码投影，不应与早期 651 节点运行 IR 或其他证据模式的节点数直接比较。“最细”也限于抽取器已经获得的事实；未知调用、没有观测到的动态分支和内核内部实现不会因为展开而自动成为已知。

## 已验证范围与尚未完成的范围

已有审核 `verification/branch-tail-stages/current/source-expandability.json` 确认，当前 Transformer 输入的原始源码投影可以恢复全部 **3371 个节点、3663 条边**，所有 canonical ID 可见，原始 IR 没有被改写。2026-10-21 对同一输入重新运行恢复检查，数量与完整性结论一致。

这证明的是当前已抽取事实的保留与投影完整性。它不证明数千节点同时完成 SVG 路由、文字排布及浏览器流畅交互，也不证明任意 Python 动态行为已被抽取。画布的 `detailed` 预设仍受焦点、策略和预算影响，不能直接等同于全部原始节点同时可见。

最近完成的 `branch-tail-stages` 审核中，Transformer 默认语义图为 89 个图元、97 条边；局部末端摘要改善了紧凑程度，仍未达到专用参考的整体模块表达和版式目标。节点数量少本身不能作为接近目标的证据。后续实现及正在生成的图组审核产物，在独立审核和目视检查完成前，不计作新的完成阶段；局部详图也不替代主架构图的接近度验收。

## 通用优化的验收方式

生产规则根据局部计算与边界事实工作，例如串联、同源分叉、汇合、旁路、重复、条件和外部上下文；相同事实出现在陌生或混合模型中，应能复用相同表达能力。

需要分别验收：

1. **语义架构状态**：已证明的模块与关系表达清楚，端口、主路径、分支和旁路没有误导，实际 SVG 的组织逐步接近参考。
2. **细节可追溯性**：摘要可展开，原始成员和绑定可恢复，保存重开后保持所选状态，未知及控制边界没有被吞没。
3. **大图可用性**：单独验证数千节点的排版成本和交互体验；必要时以局部展开、焦点图和证据图组承载细节。

这三个目标应分别报告，不能用“底层数据仍在”代替大图可用性验证，也不能用“看起来接近参考”代替语义与端口核对。
