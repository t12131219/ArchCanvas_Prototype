# 语义折叠状态与最细源码展开

目标是在同一份通用事实图上，形成一个模块逻辑和视觉组织尽量接近专用架构图的语义状态；该状态之下仍保留更细的展开能力。专用 Transformer `01093cc06a87b35a` 的展开图是表达质量参照，不是通用图的展开下限或节点数量目标。

## 如何理解“从细节折叠成架构图”

可以从信息保留角度这样理解，但实际生成流程不要求先把数千节点全部排版，再逐层收起。系统先保存原始事实、识别有证据的局部关系，再选择当前可见的语义前沿，投影真实边界并布局。用户可以从概览开始，也可以从局部细节向上收起。

优化时，细事实提供保真依据，架构表达目标决定哪些内容当前应组合或展开，实际 SVG 审核决定布局是否接受；三者共同作用。仅减少可见节点数不能保证接近专用图。“展开全部”也应结合当前表达模式理解，论文视图的细节状态不自动等同于原始源码投影全部显示。

因此，专用图的“完全展开”对应通用图中一个合适的架构语义状态；这个状态下面还可以查看角色、计算步骤和已提取的源码明细。折叠也包含有证据的重新分组、端口映射与版式重排，不能仅靠隐藏节点获得架构表达。中间状态接近专用参考是优化目标，尚非已完成结果。

```text
概览
  ↕
架构语义状态 ← 希望在此接近专用图的展开表达
  ↕
局部角色、计算步骤、具体代表与其他调用
  ↕
已提取的原始源码事实
```

这只是阅读层级示意，不表示每个模块都使用相同层数，也不表示全部语义关系能构成一棵树。同一张图可以同时展示重复区域的摘要、一个代表的内部计算和某处未知调用的真实接口。

## 折叠保留什么

折叠改变当前表达，不删除 canonical IR。端口与操作数绑定、条件、状态、对象身份、调用位置及源码来源需要可追踪。配置或透明包装可能成为可检查附注，不要求每个原始节点都只能通过双击同一个框恢复；源码投影与局部详图也是细节入口。

代表调用也不代替所有实例。已证明的重复可以显示具体代表及后续调用摘要，继续展开时恢复各次调用的身份。结构相同不意味着参数共享或输出相同；异构、未知、可变和共享身份边界不得被外观相似性抹掉。

布局需要随可见状态重新组织。例如来源分组、角色并排、旁路和外部上下文通道应由局部事实驱动，而不是仅缩小或隐藏原来的节点框。生产规则不能依据模型名、案例 ID、源码哈希或专用坐标触发。

长源码路径现在可以在精确审核通用 Stage 外框的成员和切边后，折叠成一个依赖路径摘要。连续同类调用只压缩标题中的调用次数，每次调用及配置仍独立保留。例如一个陌生计算路径可以从 5 个图元的摘要，逐步展开为 12 个图元的中间外框、19 个图元的计算操作，再切到 34 个原始源码节点；收回后恢复相同 SVG。显式角色请求仍优先于自动摘要。详见 [长路径审核](serial-paths.md)，这项能力不代表专用 Transformer 的整体收敛已经完成。

局部详图还可以在整块过大或只展开部分角色时，提供较小的嵌套源码范围、局部关系和单次调用备选。实际编辑器已检查“6 主图 → 7 局部 → 保存重开 7 → 返回 6”及“6 → 15 嵌套 helper → 6”；入口可用“更多详图”继续访问。见 [局部细节备选](detail-alternatives.md)。该细节入口阶段没有改变 Transformer 主图。

自动角色视图现在还会共同选择同一预算范围内相近局部区域的默认展开层次，减少遍历顺序造成的一处展开、一处折叠。各处调用仍独立，可以单独打开；明确关系请求与受保护边界保持独立。这改善了固定 Transformer 主图的顶部对齐，但没有完成专用参考收敛，且交叉数略有增加。见 [局部粒度一致性](coherent-frontiers.md)。

## 当前已验证的边界

`verification/sample-frames/current/source-expandability.json` 记录当前输入的原始源码投影恢复了 **3371 个节点、3663 条边**；全部 canonical 节点 ID 与边 ID 保留，原始 IR 不变。该检查使用 `tools/audit_source_expandability.cjs`，明确不执行完整 SVG 路由。

因此，“仍然保留上千节点那一层”在当前输入的事实图与源码投影层面已验证；“数千节点同时展开后，SVG 路由和浏览器交互都流畅、可读”仍需独立验证，不能由节点恢复检查推出。不同抽取版本、证据模式和输入记录的节点数也不应直接等同。

界面的 `overview/modules/semantic/roles/detailed` 属于展示粒度，`source/runtime/merged` 属于证据范围。`detailed` 仍可保留重复、配置和局部语义摘要，不是“全部原始节点同时可见”的承诺。“最细”仅指当前已提取的事实，不表示任意 Python 行为都已被解析。

验收应同时检查：语义架构状态是否更清楚且有依据，局部展开与收回是否保真，源码事实是否完整可恢复，以及同一规则在其他完整、陌生、残缺和混合模型中是否成立。当前尚未完成与专用参考的全面语义及视觉收敛。
