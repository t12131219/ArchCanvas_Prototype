# 语义折叠与最细事实的关系

目标是在完整事实图上形成一个合适的中间语义状态，使通用图的模块逻辑和视觉组织尽量接近人工认证、设计过的架构图。专用 Transformer `01093cc06a87b35a` 的详细视图是该中间状态的评价参考；它不是通用图继续展开的下限。目前尚未完成与专用图的全面对齐。

概念上可以从详细事实逐步理解为以下层次。这些是说明层次，不是固定的界面档位，也不要求整张图采用同一深度：

| 表达层次 | 主要回答的问题 |
|---|---|
| 原始事实与证据 | 有哪些调用、算子、操作数、条件、来源和运行观测？ |
| 局部计算与角色 | 哪些输入参与分叉、投影、变换、加权、汇合、旁路或状态传递？ |
| 架构语义主图 | 主要模块怎样连接，哪些关系决定整个结构？ |
| 整体概览 | 有哪些主要阶段和已证明的重复结构？ |

希望接近专用图的是“架构语义主图”附近的一个可配置状态。它下面继续保留角色、局部计算和源码证据；它上面可以进一步压缩为概览。局部展开可以只打开一条路径，其他区域仍维持摘要。

实现时不必先渲染全部最细节点。系统保留 canonical IR，根据语义证据和展示请求直接生成当前可见投影，再布局与路由。折叠不仅改变可见性，还要组织可见端口和真实依赖，并为摘要及未直接显示的事实保存映射。语义关系可以重叠，因此这不等价于沿源码父子树统一增减一个深度。

优化方向应从专用参考学习可泛化的规则：证据支持的局部语义认证、重复结构的代表性表达、串联阶段、分叉汇合、来源对应、旁路与上下文通道，以及语义收益和实际布局成本之间的选择。生产规则不得通过模型名称、案例 ID、源码哈希或专用坐标决定表达。未知、条件、状态、共享身份和操作数绑定不能为了视觉相似而消失。

`source/runtime/merged` 选择证据范围，与语义折叠粒度是不同维度。恢复源码事实不能冒充已恢复所有运行实例，更不能代表任意输入、任意执行行为都已解析。

## 已验证的范围与尚未验证的范围

2026-10-21 使用当前实现重新执行：

```sh
node tools/audit_source_expandability.cjs verification/helper-contracts/current/Transformer-current.json /tmp/archcanvas-folding-expandability.json
```

该输入的 SHA-256 为 `b1848176e4dc66c7cf4add5656684e5cc686a97532e39fe3e0d51eafff2315cb`。检查结果为 3371 个 canonical 节点、3663 条 canonical 边全部在最细源码投影中可见，节点与边 ID 集合完整，IR 未改变。这证明当前语义摘要没有删除这份输入的底层事实。

这项检查不执行全图 SVG 路由，也不测量数千节点在浏览器中的布局耗时、交互性能或文字可读性。编辑器某次“展开全部”的作用范围也必须按实际保存状态和可展开容器单独核对，不能仅凭该按钮名称断言它已显示全部 canonical 事实。

因此，当前可以确认“底层细节保留且可恢复”；“从语义主图顺畅地逐级展开到数千节点，并且始终保持良好布局与交互”仍需独立验收。验收还应检查折叠返回后的状态、实际 SVG 的端口和操作数绑定，以及陌生、残缺、混合模型上的同类行为。

## 当前问题的明确对应

“从最细节点逐步折叠，在某个状态接近专用详细图”符合信息关系上的目标。实际生成时可直接选择这个中间状态，无须先渲染几千节点；该状态也应允许按区域继续展开或进一步折叠。专用图的完全展开状态不是通用图的粒度上限。

最新已完成的[源码展开投影检查](../verification/coincident-ports/current/source-expandability.json)仍记录 3371 个节点、3663 条边全部可见，原始 IR 未改变。这证明底层事实保留，不证明任意语义预设的一次“展开全部”就能呈现全部事实，也不证明数千节点完整 SVG 的路由与交互性能。上述限制仍需按实际界面和输出单独验收。当前[端口排序审核](coincident-ports.md)只改善同一语义状态的几何，模块标题仍可直接穿行。

后续[完整源码与定位审核](source-navigation.md)已实际导出并检查该 3371/3663 输入的全部源码路径，包含编辑器折叠恢复及按当前图元定位。它补足了这份输入的完整 SVG 路由证据；浏览器延迟/帧率、整图可读性和任意预设的展开范围仍不能由此推断。概念上的中间语义状态与底层事实之间的关系保持不变。
