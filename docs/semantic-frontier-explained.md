# 语义中间状态与最细展开

目标是在完整事实之上形成可继续展开的语义中间状态，使其模块逻辑和视觉组织接近专用参考 `01093cc06a87b35a` 的详细图。专用图的“完全展开”是该专用 IR 的展示下限，不是通用 IR 的展开下限；参考图仅用于评估。

## 如何理解折叠

可以将其理解为最细事实经过语义组织后得到不同折叠状态。但生产过程不必先把所有节点布局，再逐个收起：系统从完整 canonical IR 中选择当前展示范围，再投影端口、布局和路由。自动选择也可以从紧凑状态开始，按证据、表达收益和画面成本逐步展开。

语义关系可能重叠，展示需要选择容器和边界，因此它也不只是按源码父子树设定统一深度。主图中的不同区域可以采用不同粒度。

| 展示范围 | 主要用途 |
| --- | --- |
| 架构概览 | 阅读主要阶段、重复结构和外部输入输出 |
| 语义中间状态（对照目标） | 阅读主要计算模块、分支、汇合、旁路和上下文关系 |
| 局部详细状态 | 展开某个模块中的调用、运算和参数绑定 |
| 原始源码或运行证据视图 | 查看已抽取的最细事实及其来源 |

这些是概念层次，不代表四个严格对应的 UI 按钮。源码/运行/合并是证据模式，与展示粒度属于不同维度。继续查看细节可能需要局部展开或切换到源码证据视图，不能声称当前论文视图单击“展开全部”就必然产生完整原始事实图。

## 保留细节的含义

折叠是展示投影，不删除 canonical IR。内部事实仍有来源映射，跨区域连线仍须保留原始操作数、结果槽和条件等绑定。语义展开可以揭示原来的调用和运算；未知调用只展示已知边界，不虚构其内部实现。这里的“最细”指当前抽取证据能支持的最细层级。

这项检查只验证事实保留与投影完整性，没有执行这张数千节点图的完整 SVG 路由，也没有验证其浏览器渲染与交互性能。小图上的真实折叠、源码展开、保存和恢复另有 UI 验证，不能外推为大图性能结论。

## 通用性和完成边界

优化规则应依据串联、分叉、汇合、重复、来源身份、端口角色、条件和状态等可证明关系组织画面；不能依据 Transformer 名称、案例 ID、源码哈希或参考坐标制定生产规则。规则需要在陌生及混合结构上验证。

成功条件是：通用图的某个语义中间状态接近专用参考的详细表达，同时仍能追踪和展开更细事实。当前具备中间粒度和原始事实投影能力；与专用参考的整体收敛，以及数千节点完整 SVG/UI 性能，仍未完成验收。
