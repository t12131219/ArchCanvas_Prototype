# 双语义前沿：展开参考与折叠参考

2026-10-22 用户新增要求：在已有“通用图某个中间语义状态接近专用 Transformer 完全展开图”的目标之外，增加“进一步折叠后接近专用图完全折叠图”。两档共享同一份源码事实与语义认证，均保留继续细化能力。本文是目标和验收约定，**不表示两档收敛已实现**。

```text
F0 语义概览 ≈ 专用图完全折叠形态
  ↕ 按局部语义边界展开 / 收回
F1 架构详图 ≈ 专用图完全展开形态
  ↕ 继续展开角色、子计算和 helper
F2… 已提取的计算、调用和源码事实
```

“完全折叠”以用户截图中的必要骨架为准，而非将通用图所有容器收成根节点。专用编辑器的最低折叠状态仍展开主要区域，保留 attention、FFN、Add & Norm 等子模块，只收起其内部实现。因此目标是**选择合适的语义边界**，不是最少节点数或统一容器深度。

## 两档分别需要表达什么

| 要求 | F0 语义概览 | F1 架构详图 |
|---|---|---|
| 主要计算阶段 | 显示有证据的子计算摘要及顺序 | 展开摘要中的主要计算与角色 |
| 残差、状态、条件、外部上下文 | 在折叠边界上仍明确可追踪 | 映射到准确内部捕获点和消费槽 |
| 重复 | 标明已证明范围、代表及对象身份边界 | 可检查代表内部及各次调用差异 |
| 辅助实现 | 可折入已审核摘要或来源附注 | 按解释需要选择性展开 |
| 未知与不完整结构 | 保留未知接口和影响范围 | 展示可证明的局部计算，不补齐未知部分 |
| 细化入口 | 能定位对应 F1 区域 | 能继续查看更细事实及源码 |

F0 可以有较少的直接内部计算目标，但必须满足它自己的概览目标。被折叠的 F1 内部目标应明确转到细节入口，不得因为 accounting 中有归属就报告为在 F0 直接可见。不能让自动空间预算把 F0 降成无法辨认关键阶段的空壳。

## 用户截图的参考清单（仅供评估）

1. 两条主要计算路径及重复层范围能分辨；它们的组织来自实际依赖和重复证据，不能通过 Encoder/Decoder 名称强制生成左右两栏。
2. 一侧保留 self-attention、前馈与对应 Add & Norm；另一侧保留 masked self-attention、cross-attention、前馈与对应 Add & Norm。内部投影、轴变换和矩阵运算可以收起，仍能展开。
3. 每处 residual 的真实捕获点与汇合关系可追踪，不能把旁路变成普通顺序链。Post-LN 等属性仍须由实际认证支持。
4. 编码结果到另一路消费点的跨区上下文连续可读，K/V 等角色只在证据成立时标注。折叠后 memory 的来源不能丢失或错误接入当前输入。
5. 两路输入、embedding、位置处理与实际输出路径保留。截图中的 `Softmax outside Transformer.forward` 是说明，不是该 forward 的执行节点；同理其他位于被分析入口之外的操作只能显示为明确注释或已证实的外部关系。
6. 主区域与子阶段边界清楚，重复内部不占满画面，字体可读；重点比较分组、主链、旁路、上下文和空间分配，不要求像素、节点数、颜色或坐标相等。展开模块标题继续允许连线穿过，实际节点和无关模块主体仍避让。

已保存的专用参考为 `verification/generic-convergence/current/reference-collapsed.svg` 和 `reference-expanded.svg`，来源是专用编辑器实际 DOM，分别为 23/25 和 83/85 个可见节点/边。这些数量只标识参考版本，不作为通用图的目标节点预算。专用程序静态导出、编辑器递归展开和源码 IR 的节点数属于不同投影，不应混用。

## 通用实现方向

采用已有局部事实构造候选摘要，给每个候选明确的核心阶段、原始成员、切边与细化入口。按当前阅读目标选择局部前沿：F0 保留阶段及跨界关系，F1 选择角色和内部计算；未见结构也按相同依赖、条件、状态与来源规则工作。F0/F1 是验收代号，不必成为 UI 的固定深度，也不预设现有 `overview/modules/semantic/roles/detailed` 与之逐一相等。

折叠之后重新投影可见端口和布局约束。内部 residual 可以在已认证摘要内成为明确标注，跨摘要旁路仍需真实路径；外部上下文、状态、条件、共享身份和逃逸输出不能被合并为无区别的单条普通边。未知调用不得被当作透明包装。保留配置和源码的检查入口，不通过删除事实降低密度。

布局按串联、分叉汇合、旁路、外部上下文、状态与重复区域组合。由依赖关系决定并列候选和主链顺序，再按实际 SVG 评价紧凑程度与路径冲突。任何模型名、案例 ID、哈希或参考坐标都不能参与生产选择。

## 每轮验收与状态

后续涉及前沿选择的轮次应同时固定 F0/F1 的输入、状态和生产版本，并分别输出 SVG、可见语义对应、未表达目标、几何指标和截图。只涉及局部事实或路由的轮次应说明影响哪一档；不得用另一档的结果替代。

| 验收项 | 当前状态 |
|---|---|
| F0 与专用完全折叠形态的语义和视觉收敛 | 待完善，不能仅以现有 overview 命名认定通过 |
| F1 与专用完全展开形态的语义和视觉收敛 | 持续优化，整体未完成 |
| 同一规范 IR 下 F0 ↔ F1 的可追溯映射 | 需对选定的两档联合验证 |
| F1 继续局部展开及源码事实保留 | 已有局部证据，不能替代新双档联合验收 |
| 保存重开、F0 → F1 → 更细 → F0 | 需对最终选定状态做真实 UI 验收 |
| 未见、残缺、条件、状态、共享及未知组合 | 每次规则改变均需相应泛化回归 |

前一增量新增可缩放画布的“阶段概览”作为 F0 候选，复用通用认证阶段和 helper 摘要，并停在已认证复合模块边界。Transformer 当时粗档为 40 图元/46 连接，原有 F1 三张细节图不变；双档整体收敛尚未通过。该增量的实际对照、可逆展开和剩余差距见 [阶段概览增量](stage-overview.md) 及 `verification/stage-overview/current/review.html`。

后续源码读取路径摘要将同一 stages 粗档进一步收为 30 图元/37 连接（848×1830），保留来源、消费槽、共享身份与更深展开。线长下降而交叉从 7 增至 9，不能将节点减少等同于视觉达标；F1 三张旧状态 SVG 不变。974 项测试及 42 张 SVG 审核通过，详见 [源码读取路径增量](source-read-paths.md)。双档最终交互、整体比例与上下文线路仍待联合完善。

至少在无模型家族名称的分支/旁路/重复组合上验证同样的两级摘要；再删除局部算子、插入未知调用、改变状态/条件绑定，确认只有受影响范围降低语义承诺。改名与 helper 重构不能改变事实判断。F0/F1 都要区分“底层事实保留”“当前直接表达”“由细节图补足”和“未知”，不把最细展开能力当作任一架构前沿已达标的证据。
