# 同源分叉共用绘图通道

本轮从人工架构图提取的通用经验是：一个已知输出被多处使用时，可以共用一段有明确分叉标记的通道。选择依据是实际可见来源、resolved source、输出槽及节点几何，不使用模型名、类名、案例 ID、源码哈希或专用坐标。它适用于陌生算术组合，也可用于 Transformer 的同源投影输入。

这一步放在完整最终几何管线末尾，因此自动前沿评估看到的是实际结果。它只调整路径，保留 canonical IR、可见节点、语义前沿、每条原始边、物理端点、操作数、条件、状态、共享身份及源码归属。相同通道不表示新增计算、参数共享或调用合并；SVG 中每条边仍可单独检查，圆点记录所对应的 resolved source、输出槽和边 ID。

## 适用范围及联合布局

目前处理同一来源的 2–6 条普通依赖：来源为闭合节点，消费端处于同一行，源端向下、消费端向上，并有足够纵向距离。不同 resolved source 或输出槽不分组。条件、迭代、状态、已有语义通道、bundle 和带角色标签的用途继续保留原路由；不以它们妨碍布局为由隐藏证据。圆形加法、乘法节点依据节点顶边判断所在行，实际曲面端点保留。

每张图至多检查八组。两种来源共同进入同一组消费节点时，额外尝试至多三对联合候选，每对比较两种相隔 16px 的横向分叉通道。不同值仍保持独立；逐组贪心通过不能代替联合测量。

实际路由器与新候选共用障碍计算。展开标题继续允许穿过；计算节点、固定参数、无关模块主体及原端口标签仍为障碍。已有标签保持原位置。手动偏移、标题强制避让、印刷模式、路由或标签失败，以及超出 128 条边的图跳过此步骤。`paperSharedFanouts:false` 可禁用。

## 两种线长必须分别报告

可见线条长度对同源重合段只计一次；原有 `wire_length` 仍按每条边累计，含各条边共用的路段，不修改旧指标的定义。

保留分散的源端点需要短距离汇入共享主干，因此累计线长可能增加。候选要求每组可见线条至少减少 20%，额外累计线长不得超过原源端点到共享主干的横向距离之和的两倍。这个上限来自真实端点几何，不借助全图其他长线放宽局部绕行。交叉、无关接触、不同值的重合、画布、字号、路由失败、标签缺失和质量问题不得增加；此前直接表达目标及已实现关系必须保留。

## 审核与复现

基线冻结于 `ea77524`。小案例使用隔离加载的真实旧渲染器；三张大型基线复用该提交对应的实际 SVG、同输入和同请求布局文件，逐项校验捕获及实现哈希。28 个小图状态包含五份新抽取的源程序；源文件只作静态分析，不执行其中的未知调用。

独立 Python 程序读取 62 张正式 SVG，重算正交路径、共享线段并集、分叉的几何度数、实际障碍、物理端点、逐条 canonical 绑定、条件、accounting 及直接表达目标。还比较完整文字、节点几何、标签位置、无关路径和既有 applied 约束。审核曾发现两处无关标签被重新排放，最终实现改为保留标签，并拒绝碰到它们的候选。

回归覆盖不同输出槽、不同来源、未知边界、条件、状态、共享及可变操作、真实障碍、曲面端点、标题通行、标签保护、保存重渲染和折叠恢复。最终测试报告、浏览器实际路径和文字检查、截图及文件哈希由 `completion-report.json` 绑定，不用历史通过数代替本轮结果。

本轮最终结果为 78 组、884 项测试通过，62 张正式 SVG 独立审核通过。浏览器读取同样 62 张 SVG 的实际路径及分叉标记，与保存文件逐项一致；1114 个节点及端口标签的文字未发现越界。文字检查使用原生渲染后的 `getBoundingClientRect()`，按 SVG viewBox 比例换算 1px 容差；浏览器接口未提供 `getBBox()`。另保存主图局部和陌生组合的实际浏览器截图作目视审核。

原始源码投影仍恢复 3371 个节点、3663 条边和全部 canonical ID，IR 未改变。该检查没有执行数千节点全图 SVG 路由或浏览器性能验证。本轮也没有新增编辑器文件导入导出的 UI 试验。完整目标保持进行中，仍需继续改进模块组织、跨区上下文与局部语义细节的组合表达。
