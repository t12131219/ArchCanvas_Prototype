# CPU 观测在源码结构内衔接

用户指出原“合并”图实际上把源码图和 `CPU observed execution` 两棵树并排放在同一个画布中。证据来源需要区分，但不能以此代替调用位置与数据流的衔接。

## 当前行为

原生通用画布的“证据 → 合并”现在以源码结构为主。对能够唯一定位并核对张量输入输出的静态未知调用，在原节点内部展示所选 CPU 样例的实际算子，通过原有源码输入/输出关系连接上下游。不再在普通合并图底部附带整片运行树。源码已解析的计算保持原有表示，避免重复绘制源码操作与其观测算子。

- **源码**：保留原静态结构。
- **合并**：源码结构加可核对的局部 CPU 计算；通过“CPU 补证样例”选择一组输入与模式。
- **CPU 轨迹**：保留完整原始运行树，所有样例、调用、参数和算子仍可展开。

展开/收起局部调用、F0/F1、继续细化、全部展开、图文档保存与重开均复用原生画布。界面及节点检查器显示样例、模式和仅对已观测输入成立的范围。未知调用在规范 IR 中仍是 opaque；展示成可展开模块不意味着已证明任意输入上的实现。

新补证 IR 默认打开合并图。未携带新衔接索引的既有案例保留原来的默认源码视图，不改变目录案例的默认展示。旧凭据选择合并后仍可查看源码结构和完整 CPU 轨迹，但缺失精确调用/返回结构的旧记录不能被强行接线；需要从原始源码 IR 重新运行补证。

## 衔接依据

`semantic_adapter/runtime_worker.py` 在原有只读隔离执行中增加：

1. 模块调用时的项目源码栈，包含文件、函数、起止行列；Python 3.11 的帧位置可区分同一行的不同调用表达式。
2. 模块输入的实际张量身份及对应位置参数/关键字参数槽位。
3. 完整的调用进入/退出身份，以及返回值是否为单个 Tensor。

没有包裹源码调用表达式，没有改写外部模型以猜测其对象身份。原有分支观测机制继续保留。

`semantic_adapter/source_runtime.py` 建立 `source-runtime-integration/1` 索引。采用区域需要满足：

- 静态来源版本、构造参数及运行规格一致，隔离与源码未变化检查通过；
- 该次运行成功、未截断且同种子重放输出一致；
- 完整模块调用能唯一对应到一个源码调用表达式；
- 区域内无状态写入，进入区域的张量能精确对应源码操作数槽位，参数/缓冲区身份独立保留；
- 单个 Tensor 返回值由区域内算子产生，其张量身份和输出槽可核对。

同一源码调用在同一运行中执行多次、嵌套区域相互重叠、同源多处调用难以区分、结构化或别名返回、输入重复使用缺少专用接口、状态修改、仅有行号或失败截断等情况不强行内联。索引反映的是保守支持范围，不代表未知模块已全部补全。

Python IR 校验会重新推导索引，防止保存文件中的错误桥接元数据被采用。前端也核对调用跨度、区域成员、运行算子、张量输入输出与原始连接；不能仅凭索引提供的 ID 创建连接。

## 规范事实与展示连接

`yworks_edge_router_lab/source-runtime.js` 仅生成展示用 IR：

- 原未知节点的 ID 作为局部 CPU 区域外框，规范节点本身不改写；
- 规范运行算子复用原 ID，参数共享对象不复制；
- 源码连接的展示端点指向已证明的运行算子槽位，`runtime_bridge` 保留原始完整源码连接、运行连接、张量身份、调用及样例；
- 经过源码别名摘要的连接继续携带所有衔接凭据；
- 相邻补证调用之间只保留一条展示依赖，原运行连接作为附属凭据保留；
- 未显示的运行包装节点、其他样例和已知操作的冗余观测归入 attached 账本，可从完整 CPU 视图检查。

最终节点/连接账本仍恰好覆盖完整规范 IR 的每个 ID 一次。完整 IR、运行凭据、未执行分支、原始操作数、源码位置均保存在图文档中。前端按 IR 与样例缓存局部展示准备结果；拖动继续使用原有语义切面与几何校验，不在拖动时重跑 Python 或 CPU 探针。

`generic-semantic.js` 负责接入可逆状态和账本，`generic-controls.js` 提供样例选择及检查器，浏览器主线程和路由 worker 均加载同一适配器。原生布局版本升至 15；旧 14 版源码图几何可继续读取，旧合并图需要重新构图时会将原布局保留在 migration 中。
