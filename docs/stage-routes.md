# 通用粗档：最终语义前沿上的局部路由捷径

本轮从 `38a2d66` 增量修改通用 renderer：既有固定端点捷径也可用于最终 `stages` 前沿。它在完整摘要、来源标题及布局选择完成之后运行，不根据模型名、案例 ID、源码哈希或参考坐标选择路径。粗档 F0 对照专用完全折叠图、细档 F1 对照专用展开图的双目标继续保留，整体目标尚未完成。

只缩短已经存在且有交叉的折线路径，不移动节点，不改变源/目标边侧、物理端点、规范结果槽、成员或原始绑定。候选必须同时减少交叉和总线长，且不增加尺寸、字号损失、冲突、标签侵入或路由失败。原有束线、共享来源、状态及通道排除条件继续生效。每条采用记录保留独立重新求值后的直接目标及摘要目标；已经兑现的摘要文字与规范切边不能因路由优化丢失。roles 的原有处理顺序保持。

Transformer F0 仍为 848×1676、28 图元／37 连接；三张固定 F1 SVG 也逐字节不变。因此这次是有真实普通源码收益的通用增量，**没有新的 Transformer 视觉收益**。F0 的整体比例、输入和上下文线路、说明密度，以及 F1 的整体视觉组织仍有差距。不能把局部路由改善称为双目标已完成。

临时副本另外探索了粗档外部输入停靠，全部不采用：三个候选输入一起停靠出现 13 处交叉，分别单独停靠为 15、10、10，均高于当前 9。该探索没有进入生产规则或正式通过统计，其临时产物位于 `/tmp/archcanvas-stage-docks-probe/`，不作为持久验收证据。
