## 继续清理

工具默认只列出候选，报告路径必须是尚不存在的新文件：

```bash
python3 tools/prune_verification_layouts.py --report /tmp/verification-layout-plan.json
```

确认范围后执行：

```bash
python3 tools/prune_verification_layouts.py --apply \
  --report verification/storage-cleanup/another-run/manifest.json
```

`--apply` 会直接删除符合条件的生成文件，不提供回收站恢复。工具会在第一次删除前重新核对候选集合，并记录路径、大小和修改时间；对所有保留文件执行前后哈希校验。报告路径不得覆盖旧报告。执行期间应停止相关采集/导出任务，避免清理正在写入的产物。

脚本中的三个保护目录对应本次活跃工作，**不会自动按时间更新**。未来需要调整时，应先查清当前基线和测试引用，再明确修改保护范围。

## 重新审核历史轮次

删除的是重复包含完整 IR、几何和诊断的布局导出。历史 SVG、截图、审核页、输入和紧凑报告均保留；HTML 中指向已清理布局 JSON 的下载链接，以及直接消费这些布局的历史检查脚本，需要重新生成布局后才能使用。保留哈希清单不等于保留原文件本身。

应按对应轮次的文档、`tools/audit_*.cjs` / `export_*.cjs`、采集报告中的输入和 state，以及记录的生产版本重新生成。精确复现旧布局需要原实现；不能用当前实现替代旧版本后宣称哈希应当相同。某些旧采集脚本还依赖当时的临时冻结目录，应从已记录提交或保留的冻结实现恢复它。
