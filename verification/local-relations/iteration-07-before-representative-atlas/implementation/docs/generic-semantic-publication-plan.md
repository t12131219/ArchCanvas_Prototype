# 通用语义认证与架构图表达：可行性和实施方案

目标是让通用层具备人工设计架构图时采用的判断能力：从证据建立角色、选择展示边界、安排阅读顺序、压缩重复、分配细节、审核结果。不能以模型家族、源码类名、案例 ID 或源码摘要触发模板。完整模块名称可以是认证结果，不能成为绘图前提。

本文区分目标设计和当前已经验证的能力。当前阶段证据见 [local-relations.md](local-relations.md)，不能把方案描述当作完成记录。

## 1. 可行性与能力边界

这条路线可行，因为人工图中相当一部分判断可以转化为有限、可检查的关系：同值分叉、不同操作数汇合、跨区域上下文、局部旁路、状态接口、条件范围、对象身份和结构重复。它们广泛存在于不同网络和普通张量程序中。

| 人工设计经验 | 可泛化的能力 | 需要的证据 |
| --- | --- | --- |
| 几个相关分支并排 | 来源分组、端口角色对应、分叉与汇合 | 真实值来源、操作数槽、消费端口 |
| 跳连走独立旁路 | 局部旁路原语 | 捕获值、内部计算、准确汇合端 |
| 外部上下文走侧边 | 跨区域输入通道 | 外部生产者、各消费点及当前折叠映射 |
| 重复部分只画代表 | 结构分组及代表选择 | 操作、配置、条件、对象选择与边界对应 |
| 主图简洁，细节另图 | 局部表达和图组规划 | 必须表达的关系、实际尺寸、未完成目标 |
| 看图后修订 | 可复现的语义、SVG和目视审核 | 冻结输入、独立检查、截图与失败记录 |

不能把人工图预先知道的结论直接写进通用层。普通环不是时间轴，形状相同不是参数共享，重复调用不是结果相等，若干归一化与矩阵运算也不自动证明完整架构。源码和特定输入上的运行记录均有适用范围；无法恢复的 Python 行为必须保留未知边界。

因此，合理承诺是：证据充分的部分准确表达；陌生但依赖可解析的部分按计算结构表达；无法解析的部分保留真实接口。不能承诺任何陌生程序都自动达到人工论文图的完整语义精度。

## 2. 分开证据模式、表达方式和展示粒度

三个选择应互相独立：

- 证据模式：源码、运行、合并，回答事实从哪里来。
- 表达方式：架构图、计算结构、证据浏览，回答当前要解释什么。
- 展示粒度：概览、角色、计算、源码细节，回答每个区域展示多少。

同一源码架构图可以折叠重复结构，也可以叠加某次运行的形状和分支观测。某次运行只观测到一条路径时，不能因此删除源码中的其他路径。合并运行记录可按调用来源建立附属证据，不能仅因调用目标相同就合成一次计算。

## 3. 建立有范围的局部事实

建议链路为：

```text
原始事实图
  → 局部关系及各自证据
  → 候选展示区域
  → 局部表达与图组计划
  → 可见端口及约束投影
  → 实测尺寸、布局和路由
  → 事实、表达、SVG、目视审核
```

局部事实应包含命题、成员、输入输出角色、证据边、前提、适用范围及未解决属性。例如，证明一个乘法的某操作数来自 sigmoid，可以表达门控关系；没有前后状态绑定时，不命名为状态更新。未知调用两侧独立成立的事实继续保留，跨越未知调用的等价证明则不能成立。

认证采用可独立核查的属性集合。匹配程度或语言模型的评分可以帮助提出候选，不能替代事实证明。框架正式接口可以提供隐藏状态等契约；自定义代码必须由实际关系证明。

需要逐步扩大影响分析：未知调用可能影响输入对象、别名或外部状态。当前保守前缀屏障有助于防误标，后续精确到受影响对象和依赖范围，才能减少无关区域一起降级。

## 4. 分开源码归属、语义关系和画面容器

语义关系允许重叠，几何包含通常需要容器树。一个操作可以参与门控、残差和状态关系，但只能有一个主要画面归属；其他关系通过端口、边、括注或引用表达。

候选区域应保留内部边、输入切边、输出切边、中间结果逃逸和条件范围。选择时优先保护状态、条件、未知调用及跨区域连接，再考虑紧凑和对齐。跨多个 helper 的连贯计算可以成为一个候选区域；同一源码类中的不同阶段也可以拆开。

每个原节点和原依赖都必须有可检查的去向。隐藏到容器不等于关系已经表达；复制引用也不等于新增计算或参数实例。

## 5. 布局器消费关系约束

布局器不接收“把某种模型画成双栏”一类指令，而接收开放关系协议：

| 约束 | 几何用途 | 必须保留的语义 |
| --- | --- | --- |
| 主链顺序 | 建立阅读方向 | 真正的数据依赖 |
| 来源分组 | 同来源分支就近排列 | 每个消费端口的身份 |
| 角色对应 | 多段变换保持对应 | 上下游准确端口映射 |
| 局部旁路 | 预留绕行通道 | 捕获点和汇合点 |
| 外部上下文 | 预留跨区域通道 | 上下文来源和各消费点 |
| 状态回送 | 显式反馈方向与通道 | 状态证据范围，不能补时间含义 |
| 条件包含 | 包围受条件支配的计算 | 分支及汇合的实际范围 |
| 分派与回收 | 组织选择、计算及聚合 | 选择索引、分支和权重的对应 |
| 重复区域 | 代表、索引及范围标注 | 结构、对象和调用身份的区别 |
| 未知边界 | 保留接口及未解析区域 | 不能画成透明连接 |

每项约束记录触发证据、端口、范围、硬要求或软偏好、投影结果，以及已执行、暂缓或冲突的原因。折叠后应投影到外部端口；不能把原节点藏起来后默默丢弃关系。

事实及端口身份优先于对齐、等宽和紧凑。暂时没有几何处理器时，保留通用DAG/SCC布局并公开暂缓项。这样可以逐步增加局部表达能力，不必为每种混合模型编写整图模板。

## 6. 重复压缩采用结构对应

至少区分静态层序列、循环模板和条件分支集合。它们不能统一写成没有限定的 `×N`。

代表选择比较实际操作、框架配置、字面量、操作数顺序、条件、对象选择分区和边界。不同类可以有相同局部结构，同类也可以不同。未知元素不能因为类名相同而共用代表。

对异构序列，先建立已证明的结构组，再分别选择具体代表，并打印代表索引及覆盖位置。结构对应只能授权相应的展示压缩，不证明参数相同、结果相同、纯函数、运行次数或时间递推。

自动图组仍需额外的覆盖核查：一张代表图必须确实呈现被压缩实例要求表达的关系，并能通过对应映射回去；不同实例的特殊连接和未知边界需要独立图面，不能仅凭共同指纹计为已覆盖。

## 7. 依据表达目标分配空间

统一展开深度不适合混合图。每个区域可以选择摘要、角色关系、计算结构、源码细节或未知边界摘要。

规划器先产生必须表达的目标：外部输入输出、关键路径、分叉汇合、状态条件、共享身份及未知边界，再按已证明局部事实增加目标。收益考虑连接重要性、实例差异和用户焦点，不能只奖励熟悉模块。

成本使用实际测量的文字、容器、端口和路径，设置总图数、单图宽高、最小字号、节点和路由预算。超预算时拆图并记录目标由哪张图兑现。预算仍不足时明确列出缺失目标；一个易读但笼统的外框不能被当作全部内部计算已表达。

## 8. 每轮同时进行四种审核

| 审核 | 检查内容 | 不能单独证明什么 |
| --- | --- | --- |
| 事实一致性 | 原始操作数、条件、状态、身份、边界与认证前提 | 不能证明画面易读 |
| 表达兑现 | 所需节点、角色和依赖是否实际可见，是否有对应图面 | 不能由元数据存在替代 |
| SVG独立检查 | 真实端点、路径、障碍、标签、字号和边界端口 | 不能证明视觉阅读自然 |
| 浏览器及目视 | 字体实测、裁切、分支辨认、主链和语义误读 | 不能证明底层语义正确 |

每轮固定输入、配置、基线实现和产物摘要。分开两种对比：同一规范IR只换绘图器，用来评估展示；同一源码经过新旧抽取及绘图，用来评估完整链路。后者如果IR发生变化，必须明确说明，不能把节点减少全算作布局收益。

SVG比较应以语义节点/端口/原始边的稳定映射为依据，再比较几何。纯文本diff和整图像素相似度容易被ID、路径排序和字体变化误导。可以把目标人工图当作清晰度参考，但不以像素相似度作为通用规则的优化目标。

每次视觉自省记录：改善了什么、牺牲了什么、遗漏了什么、反例是什么、下一步要验证什么。语义正确性是硬门槛；几何指标允许有据可查的取舍，但退步不能被隐藏。

## 9. 实施与验收顺序

| 阶段 | 交付物 | 验收重点 |
| --- | --- | --- |
| A 混合验收与基础事实 | 完整/残缺/陌生/未知/动态案例，独立局部证据 | 改名不影响事实；破坏关系只撤销相关承诺 |
| B 边界与约束 | 重叠关系、候选区域、端口投影、约束执行记录 | 逃逸输出、条件、状态及未知接口不消失 |
| C 可组合几何 | 来源、角色、旁路、上下文、反馈、分派/回收处理器 | 真实路径执行约束，不能只记录“已应用” |
| D 表达及图组规划 | 实际预算、局部粒度、结构代表覆盖与省略清单 | 每个目标由可读图面兑现，预算不足诚实失败 |
| E 泛化验收 | 冻结后未见组合、外部源码、运行及资源压力测试 | 对陌生组合仍保留局部能力，不依赖模型名称 |

每阶段都要做正例、破坏反例、重构、共享及动态反例。开发时使用过的输入随后只能算回归集；修改规则后，需要新的未见组合。测试既要衡量覆盖率和可读性，也要衡量错误语义承诺、局部退化范围、约束暂缓、未知边界保留和图组目标兑现。

## 10. 当前进展及后续优先级

当前已验证的增量包括：局部关系、候选边界、部分约束消费、受限循环名字绑定、源码对象选择、运行开始时参数别名，以及按局部结构选择异构代表。证据为45个静态开发/回归输入、237项测试、45张独立SVG审核；两个CPU输入沿用既有真实receipt。本轮真实界面已检查代表选择、保存、导出和重开。

这些证据不等于完整目标通过。13项要求仍为部分完成。优先补齐：

1. 结构代表到自动图册的覆盖映射，保护实例差异和独立外部连接。
2. 统一候选区域、局部表达和图组的实际资源预算。
3. 角色对应、条件包含、完整分派/回收的几何处理器与证据。
4. 更精确的副作用范围、自定义状态、复杂循环退出和动态集合。
5. 冻结后的新未见组合、外部源码、runtime/merged及大深密集图压力验收。

当前对照也展示了取舍：混合总览由4.74pt/17交叉改善为8.77pt/6交叉；代表图增加来源字幕后由8.81pt降为8.54pt，交叉均为0；补全while运算字面量后由8.23pt/7交叉变为8.11pt/12交叉。前者是已观察的布局改善，后两者是公开保留的空间和路由代价。
