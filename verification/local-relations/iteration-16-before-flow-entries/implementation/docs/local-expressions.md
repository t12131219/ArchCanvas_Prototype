# Relation-driven local expressions

The canvas role preset now supplements certificate-owned roles with independent local relation requests. It supports gated products and joins, framework state slots, selection results, conditional interfaces, unknown/effect boundaries, iteration bindings and proven object identity. These are local facts, not complete-model templates. A request carries the original relation, targets, bindings, condition/evidence scope and properties that remain unproved.

The selector first preserves the established semantic frontier, then opens only ancestor paths needed by those requests. A reached source scope has a local budget; all direct children exposed by opening a path count toward that budget. The selector stops at certificates, condition bodies, unknown/mutable operations, observation/identity boundaries and unresolved iteration/repeat boundaries. Existing concrete sequence representatives remain independent. External producers stay external; no inferred edge replaces an auxiliary computation.

Independent budgets do not release space for unrelated automatic helper expansion. An initial experiment did that and enlarged two evaluation graphs without improving the requested expressions; the selector was corrected to supplement the original frontier after automatic selection. This distinction is covered by a regression test.

Projection receipts distinguish ready endpoints from fulfilled expressions. Final rendering must also pass the existing expression-goal checks for physical routes, exact bindings, control and visible identity, and place the relevant edge labels. Folded operations, stopped boundaries, budget limits and route/label failures remain explicit deferrals. Receipts appear in the inspector and saved architecture export. They do not claim graph-wide readability or reference correspondence.

## Remaining scope

The overall target is still an appropriate intermediate generic frontier approaching the dedicated reference, with further details below it. This stage extends local expression planning beyond certified modules; it does not solve source-helper geometry, graph-wide adaptive expression/panel selection, reference node/role correspondence, dense crossings, or the cross-language numeric digest contract. Transformer production behavior has no model-name, class-name, case-ID or source-hash trigger. The reference remains evaluation data only.
